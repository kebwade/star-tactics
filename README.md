# 科币战争 —— 巴巴博弈

一个**纯前端、零依赖**的自走棋小游戏（金铲铲之战 / 云顶之弈 那一类）。

双击 **`启动游戏.bat`** 就能玩。不需要装 Node.js、不需要 npm、不需要服务器、不需要构建。

**视觉**：淡绿 + 浅灰的「高级山谷」主题。背景是 SVG 画的四道真实曲线山脊
（越远越淡越虚）+ 两条会飘的薄雾带 + 一束斜阳 + 暗角 + 极细颗粒。
封面和游戏内共用同一套素材（`<use>` 引用，只定义一次）。

**布局**：商店在屏幕顶端，自己阵容在正中间，备战池在底端。
准备阶段**看不到对手阵容**，开战才揭晓。

**刷新 / 买经验做成大按钮**，和商店卡并排放在右边一列（金铲铲也是这个位置）：
蓝绿渐变的「刷新商店」+ 金铜渐变的「买经验」，后者上面直接写着
「升到 3 级还差 2」和一条经验进度条 —— 不用玩家自己去 HUD 上算。
买不起时压暗但仍然看得见（藏起来会让人以为按钮没了）。

**卡牌不遵循格子**：棋子卡牌比格子宽 8px、高 12px，会溢出到格外，
相邻卡牌有几像素重叠，看起来是一叠立起来的牌而不是网格里的图标。
关键在于 `.cell` 用了 `overflow: visible` —— **溢出不参与排版**，
所以棋盘的总尺寸一点没变，只是卡牌能长出来。
战斗画布上的卡牌用的是同一套尺寸规则（宽 = 格子+8，高 = 格子+12），
所以「棋盘 → 战斗」切换时观感是连续的。

## 零、怎么运行

| 想干什么 | 双击哪个 |
| --- | --- |
| **玩游戏** | **`启动游戏.bat`**（就是打开 `index.html`，效果一样） |
| **发给别人玩（手机也行）** | **`一键部署到网上.bat`** —— 发到 GitHub Pages，拿一个网址 |
| **跑自检** | **`跑自检.bat`**，按菜单选 1 / 2 / 3 / 4 |
| **改数值 / 看战斗日志** | `console.html`（开发控制台，不是给玩家看的） |

### 为什么给的是 .bat 而不是 .ps1

这台机器上 Windows PowerShell **默认禁止运行脚本**，直接跑 `tools\run-tests.ps1`
会报「在此系统上禁止运行脚本」。两个 `.bat` 启动器替你切代码页、
加 `-ExecutionPolicy Bypass`、跑完停住。**不需要改任何系统设置。**

（想让 `.ps1` 也能直接跑可以执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，
但没必要。）

### 发布到网上：别人（包括手机）打开一个网址就能玩

游戏是**纯前端、零依赖**的 —— 没有服务器、没有构建、没有接口，
所以任何能托管静态文件的地方都能放。这里用 GitHub Pages（免费、稳定、自带 HTTPS）。

**最快的一步：双击 `一键部署到网上.bat`**，它会在第一次问你要一个 GitHub Token
（脚本里写着申请步骤，勾 `repo` 权限就行），然后自动：

```
建仓库（已经有了就改成更新） → 逐个文件上传 → 打开 Pages → 打印网址
```

拿到的地址形如 `https://<你的用户名>.github.io/star-tactics/`，
**第一次要等 1~2 分钟构建**，之后每次更新也是这个时间。把地址发给别人就完事了。

不想用脚本的话，手动也就三步：
① GitHub 上 New repository（公开、**不要**勾 Add a README）；
② 把整个项目文件夹拖进仓库页面的上传区（支持拖文件夹）；
③ Settings → Pages → Source 选 `Deploy from a branch` → 分支选 `main`、目录选 `/ (root)` → Save。

★ 这个部署脚本走的是 **GitHub REST API，不需要装 git** ——
这台机器上没有 git、也没有 gh，所以脚本用 PowerShell 直接调 API 上传。
它在 `tools\部署到GitHub.ps1` 里，可读可改；Token 会存在
`%USERPROFILE%\.star-tactics-token`（**项目目录之外**，不会被打包进去）。

### 手机上是怎么排版的

手机不是"把桌面版缩小"，而是**换了一套结构**（媒体查询 `max-width: 700px`
或 `max-height: 520px`，横屏手机也走这一套）：

| | 桌面 | 手机 |
| --- | --- | --- |
| 准备阶段 | 三栏：侧栏 · 棋盘 · 侧栏 | **一列**：棋盘在上，两条侧栏折到下面，整页纵向滚动 |
| 战斗阶段 | 三栏：控件 · 战场 · 战报 | 战场在最上，控件和战报在下面 |
| 商店 | 5 张卡 + 右侧操作列 | 5 张卡按宽度均分 + 操作按钮横排 |
| 格子 | 由 `100vh` 和 `100vw` 一起决定 | **只由宽度决定**：`(100vw - 96px) / 8` |

★★ 为什么必须换结构：原来的 `--cell` 要扣掉**左右两条侧栏**（各 `min(306px, 19vw)`）
和 124px 边距，390 宽的手机上算出来只有 **2~15px 格子**；
而 `arena.js` 有一条「小于 20px 就退回默认值」的保护，于是棋盘被硬撑到 583px、
横向溢出 97px —— 什么也点不到。就算去掉那道保护，14px 的格子也没法玩。
换成一列之后，390 宽的手机上格子是 **36px**（8 列共 344px，左右各留 23px），
点得着也看得清；`gametest` 里有一整组「手机竖屏布局」守着这件事
（三种真机尺寸 × 横向不溢出 / 棋盘商店备战池都放得下 / 画布宽度 = 布阵盘宽度）。

★ 触屏上额外做的两件事：去掉点击高亮和双击缩放
（`@media (hover: none) and (pointer: coarse)`），
以及**取消悬停浮起效果** —— 那是给鼠标的，触屏上点完会留在浮起状态，看着像卡住了。

## 一、游戏里有什么

### 开始界面

- **人机模式** —— **24 关**闯关，从「见习剑士」打到「巴巴博弈」；
  打穿第 24 关之后进入**无尽模式**：随机出怪、每波敌人面板复利 +7%
- **对战模式** —— 锁着的，点了会提示「暂未开放」（下面有说明为什么不能做成 disabled）
- **设置** —— 总音量 / 音效 / 背景音乐 / 画面亮度，存 localStorage

### 准备界面长什么样

```
┌────────────────────────────────────────────────────────┐
│ 关卡 · 血量 · 金币 · 等级 · 连胜            上场 8/8 ⚙ │
├────────────────────────────────────────────────────────┤
│ 商店   [卡][卡][卡][卡][卡]        🎲刷新  📈买经验     │  ← 顶端
├───────────┬──────────────────────────┬─────────────────┤
│ 对手情报  │                          │ 回合记录        │
│ 选中/羁绊 │     我方阵容 8×4          │                 │
│ 装备栏    │  （最上面一行贴着中线）   │  ⚔ 开战         │  ← 正中
├───────────┴──────────────────────────┴─────────────────┤
│ 备战池  [ ][ ][ ][ ][ ][ ][ ][ ][ ]                    │  ← 底端
└────────────────────────────────────────────────────────┘
```

面板都竖着排在棋盘**左右两侧**，而不是横着堆在棋盘上下 ——
原因见「四·五」那一节：8 列地图很宽、两侧本来空着，
横着堆会吃掉 211px 的垂直空间，把地图挤到压住邻居。

准备阶段**完全没有敌方阵容** —— 连空位都不摆。你只有对手情报卡：
名字、威胁等级、**一句模糊的体系推测**。打起来才揭晓对面什么阵。

### 战斗界面

```
┌────────────────────────────────────────────────────────┐
│ 无尽 · 第 7 波 · 血量 · 金币 · 等级                  ⚙ │
├──────────┬──────────────────────────┬──────────────────┤
│ 我方     │                          │ 战斗回放          │
│   VS     │      8 × 8 战场          │ （事件流原文）    │
│ 敌方     │   （双方各占一半）        │                  │
│ ⏸ ⟲     │                          │                  │
│ 速度     │                          │                  │
│ 进度条   │                          │                  │
└──────────┴──────────────────────────┴──────────────────┘
```

「对阵条 + 播放条」和战报各占左右一栏，**画布独占中间**。
原来播放条压在画布下面，白占 65px —— 画布是正方形、要放 8 行，
垂直空间是它唯一的瓶颈，挪走之后画布大了 25%~80%（看分辨率）。

### 商店（对齐金铲铲）

每张卡就是一张竖长的立绘卡：**立绘铺满整张卡**，左上角费用徽章，
右上角价格，名字压在底部的暗色带里，羁绊小字在名字下面，顶部一条费用色。

**五个费用档**（灰 / 绿 / 蓝 / 紫 / 金），24 个棋子：

| 费用 | 数量 | 定位 | 什么时候刷得到 |
| --- | --- | --- | --- |
| 1 费 | 8 | 开局铺场 | 1 级就有 |
| 2 费 | 6 | 中期主力 | 3 级开始 |
| 3 费 | 4 | 成型核心 | 4 级开始 |
| **4 费** | 4 | **稀有** | **5 级 11%，8 级 34%** |
| **5 费** | 2 | **传说** | **6 级 6%，8 级 20%** |

抽卡概率表（`js/levels.js` 的 `ST.LEVEL_TABLE`，simtest 有断言守着「每行和为 1」）：

| 等级 | 上场 | 升下一级 | 1费 | 2费 | 3费 | 4费 | 5费 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 2 | 100% | — | — | — | — |
| 2 | 2 | 2 | 100% | — | — | — | — |
| 3 | 3 | 6 | 75% | 25% | — | — | — |
| 4 | 4 | 10 | 55% | 33% | 12% | — | — |
| 5 | 5 | 18 | 32% | 32% | 25% | 11% | — |
| 6 | 6 | 22 | 18% | 26% | 32% | 18% | **6%** |
| 7 | 7 | 26 | 12% | 20% | 30% | 26% | 12% |
| 8 | 8 | 满级 | 6% | 14% | 26% | **34%** | **20%** |

7 / 8 级是配 24 关加的：后半程敌人满编 8 人，玩家如果还卡在 6 人口，
就只能靠星级硬顶，体验是残缺的。代价是 7→8 级要 26 点经验（≈7 次买经验 / 26 金），
逼玩家在「升人口」和「刷牌升星」之间真的做一次取舍。

**★ 满级人口必须等于 `ST.MAX_DEPLOY`。** `battle.js` 的 `buildSide()` 会
`slice(0, ST.MAX_DEPLOY)` —— 超出的棋子被静默丢掉，界面上看不出来。
两处由 `levelcurve` 的断言锁在一起。

另外两样也是云顶商店的标配：

- **概率条**：直接显示当前等级抽到各费用卡的概率
- **锁定**：锁上之后，回合开始不会刷新商店，可以留住一张好牌

### 两张传说卡

5 费棋子的技能是**全场唯一的机制**，一张牌就能改变一场战斗：

| 棋子 | 技能 | 效果 |
| --- | --- | --- |
| 🗿 **山岳** | 不动如山 `aegis` | **给全队每个人都套一层护盾**（+620）—— 一个人就是一道防线 |
| ❄️ **张雪峰** | 万剑归宗 `whirl` | **以自身为中心斩出一圈剑气**，命中周围所有敌人（560） |

这两个技能 kind（`aegis` / `whirl`）**只有 5 费才有** —— 不然稀有度就被稀释了，
simtest 里有断言守着这一点。`aegis` 和普通护盾技能的区别是它不看目标格，
同事散得再开也吃得到；`whirl` 和范围法术的区别是它打「自己周围」而不是
「目标格周围」，所以哪怕被围住、哪怕没锁定到人，也能清一圈。

### 战斗表现

战斗中的每个单位也是一张**卡牌**：立绘 / 阵营描边 / 费用徽章 / 星级 /
装备图标 / 名牌 / 血条 / 法力条。

「自动寻敌」是模拟器里本来就有的（每 tick 选最近的敌人 → 走过去 → 进射程就打），
表现层负责**让你看得见它在寻敌**：走位位移、出手时朝目标突进、被打时后仰。

打击感清单（全都是消费同一个事件流换来的，加特效完全不碰规则）：

| 效果 | 触发 |
| --- | --- |
| 伤害飘字 | 每次伤害（普攻白 / 暴击金黄 / 技能紫 / 反弹红 / 治疗绿） |
| 命中白闪 | 被打的卡牌闪一下 |
| 屏幕震动 | 暴击 6.5、技能 4.5、阵亡 9 |
| 命中火花 | 按暴击与否喷 4~9 条 |
| 冲击环 | 技能释放 / 治疗 / 护盾 / 眩晕 / 阵亡 |
| **击中顿帧** | 暴击与技能停 55ms、击杀停 75ms —— 最有「重量」的一下 |
| **血色滞后条** | 刚掉的那一截用浅血色慢慢追上来，一眼看出「这一下挨了多少」 |
| 阵亡碎裂 | 扩散环 + 两组火花 |

### 一局怎么玩

每回合的循环是**云顶那一套**：

```
回合开始（发工资：基础 5 金 + 利息 + 连胜/连败奖励）
  → 商店买棋子（5 个格子，按等级概率抽卡，刷新 2 金）
  → 摆到棋盘上（上场数 = 等级，买经验 4 金升一级）
  → 3 个同名同星自动合成高一星
  → 装备（通关掉落，点装备再点棋子，每棋子最多 3 件）
  → 开战
  → 赢了进下一关，输了掉血重来
血量归零 → 挑战结束
```

战斗画面里你会看到双方所有棋子，那就是**你自己的这一场**。
看完整场战斗回放，可以 0.5× 慢放 / 4× 加速 / 暂停 / 跳到最后。

### 为什么「对战模式」不用 `disabled` 属性

被禁用的按钮**根本不会触发 click 事件**。如果用 `disabled`，
玩家点了没反应，会以为界面坏了。
所以这里用样式（`.locked`）+ `aria-disabled="true"` 表达「不可用」，
但点击照常处理 —— 点了就明确告诉你「暂未开放」。
`tests/gametest.html` 里有专门的断言守着这件事。

### 走位 AI：出手 → 绕路 → 换位

战斗里棋子怎么走，分三层，**顺序本身就是设计**：

```
1. 贪心一步      只走「(切比雪夫, 曼哈顿) 严格变小」的格子（保证不死循环）
2. 绕路 BFS      贪心走不动时，搜最近的可达格子 —— 优先「站上去就能打到敌人」的
3. 换位          连出手位都绕不到时，和前方队友交换位置
```

**为什么第 2 层要区分「更近」和「打得到」**：
第一版只找「更靠近目标」的格子，结果出现一个很蠢的现象 ——
**棋子会一直贴着人墙往里蹭，却永远进不了射程**。
「更近」不等于「打得到」：当所有能打到敌人的格子都被队友占着时，
它满足于「离得更近了一点」，一路绕到边上还是不出手。
现在优先找「站上去就能打」的格子，找不到才退回「更近」。

**第 3 层（换位）的三道闸门**：

| 闸门 | 为什么 |
| --- | --- |
| 换过去必须严格更靠近目标 | 否则是白折腾 |
| 优先不打扰正在交战的队友 | 他射程内已经有敌人，把他换下去等于帮倒忙（没有别的选择时才考虑他） |
| `SWAP_LOCK = 1.0s` 防抖 | 没有它会死循环：甲换到前面、乙下一 tick 又想换回来，原地互相顶 |

实测频率（预设阵容互打 100 场、玩家侧近战 275 个）：

```
走位 1824 次   贪心 1778 / 绕路 46（2.5%）
换位 0 次
「整场既没出手也没移动」的近战：0 个     ← 这条才是关键：不再有人发呆
```

把 8 个近战挤成一堆时，绕路占 **23%**、换位开始触发 ——
因为**「换位」本来就是「被彻底堵死」才用的兜底手段**，棋盘开阔时绕一下就够了。
真要看它生效，得是密集近战阵容（或者用 `tests/simtest.html` 的
「走位智商」那一节，那里有构造好的封死局面）。

### 开战站位：两条硬规矩

这两条是玩家反馈三次才定位到的 —— 前两次我都在查「行列数据传得对不对」，
而数据一直是对的。**问题在于「看到的」：移动速度曾经是一 tick 一格（30 格/秒），
开战 0.3 秒阵型就冲到中线去了，玩家根本看不到自己摆的阵。**

```
CFG.OPENING_HOLD = 0.5      // 开局定格：只打不跑
CFG.MOVE_INTERVAL = 0.3     // 走一格 0.3 秒（3.3 格/秒）
```

**规矩一：射程内有敌人 → 就地打，绝不走位。**
原来的判定是「只看当前锁定的那个目标」：目标在远处就走过去，
哪怕旁边紧贴着另一个敌人 —— 看起来就是棋子从敌人身边路过不肯打。
现在每 tick 先找「射程内最近的敌人」，有就打，没有才走。

**规矩二：射程内没人 → 自己寻敌走过去，而且带着节奏走。**

三条断言守着它们（`simtest` 的「开战站位与寻敌」一节）：

| 断言 | 守什么 |
| --- | --- |
| 贴脸的两个近战整场 0 次走位 | 规矩一 |
| 开局定格期内 0 条走位事件 | 定格 |
| 同一单位的走位间隔 >= MOVE_INTERVAL | 不会瞬移 |
| 事件流里每条 move 都必须「射程内确实没敌人」 | 规矩一（全量、逐场检查） |

最后一条写在事件流校验器里，对**每一场**战斗的**每一条** move 事件都验一遍，
所以只要有人在射程内乱跑，任何一页自检都会立刻报。

**改这些常量会影响平衡**：走位变慢等于给远程多送几秒输出时间，
「站桩肉墙」也相对变强。实测第 10 关（山岳 + 4 坦克的纯肉墙）从 +2% 掉到 −5%（打不过），
所以那关撤掉了一个输出位。跑 `levelcurve` 就能看到这类偏移。
### 战斗特效是怎么被自动验证的

**无头浏览器不驱动 `requestAnimationFrame`** —— 时间轴不会自己走，
所以「寻敌位移」「伤害飘字」「屏幕震动」这些东西看起来根本没法自动测。

解法是把时间推进和 rAF 解耦：

```js
Arena.step(dt)     // 推进 dt 秒：消费事件、更新插值、生成特效、重绘
frame(now)         // 只负责「按真实时间算出 dt，交给 step」
```

于是测试可以自己 `for (i=0;i<240;i++) Arena.step(1/30)` 把 8 秒战斗推完，
走的是**和真实播放完全同一段代码**：
`tests/gametest.html` 就是靠这个断言「特效峰值 51 个、震动峰值 11.17」。

## 三、三条架构铁律

这三条是唯一真正重要的东西。要重构，推翻别的都行，**别推翻这三条**。

### 1. 模拟层不认识画面

`js/battle.js` 不碰 canvas、不碰 DOM、不读全局可变状态。它是一个纯函数：

```js
ST.Battle.battle(setup, seed) → result
```

**收益**：战斗回放、千场批量测试、慢放/加速/跳过、难度曲线标定 —— 全都是免费的，
因为它们只是「换一种方式消费同一个 result」。

`js/arena.js`（战斗画面）就是这条铁律的活证明：它不算伤害、不掷骰子、不判胜负，
只按时间轴消费事件流。**所以打击感是可以后加的** ——
伤害飘字、屏幕震动、顿帧、血色滞后条，这些全是「读事件流 + 画东西」，
一行都没碰战斗规则，也没有引入任何不可复现的随机。

### 2. 随机只来自种子

`Math.random()` 在 `battle.js` 里**一次都不能出现**。随机只来自 `ST.makeRng(seed)`。

（`game.js` 里用 `Math.random()` 抽商店、掷战斗种子 —— 那是「这一局的走向」，
本来就该随机；但**一旦阵容和种子定下来，战斗过程必须完全可复现**。）

### 3. 输出是「初始快照 + 事件流」

```js
result.initial   // 开打前的完整面板快照（谁站在哪、多少血、什么装备）
result.log       // 按时间排序的事件数组
result.unitStats // 打完之后的统计
```

渲染层先按 `initial` 建立状态，再按顺序消费 `log`。

## 四·五、准备阶段的布局：尺寸全是算出来的，不是写死的

地图是 **8 列 × 4 行**（自己半场 32 格）。屏幕宽高差异很大，
所以格子大小不是一个常量，而是**三个上限取最小**：

```css
--cell: min(
  var(--cell-max),                          /* ① 设计上限：想多大 */
  calc((100vh - var(--cell-chrome)) / 4),   /* ② 纵向：屏幕高度挤得出来的 */
  var(--cell-w)                             /* ③ 横向：扣掉两侧栏剩下的 */
);
```

这么写不是为了优雅，是因为**写死会真的翻车**。曾经 `--cell` 是一个字面量 `96px`，
在 1366×768 上：

* 棋盘实际需要 322px 高；
* 它所在的 `.prep-mid` 只分到 142px（六个面板把垂直空间吃光了）；
* 棋盘溢出后**直接盖在对手情报条和回合记录上面**；
* 而 `body` 是 `overflow: hidden`、场景是绝对定位 ——
  `scrollHeight` 一点没变，滚动条也不出现，**不看几何根本发现不了**。

于是做了两件事：

**一、面板从棋盘上下搬到棋盘左右。** 8 列地图只有 700px 宽，两侧空着 700px，
而横着堆在棋盘上下的六个面板要吃掉 211px 垂直空间。搬进左右侧栏（`.prep-side`）后，
这 211px 全回到地图上：同一块屏上格子从 68 → 80px，地图面积 +78%。

左右两栏都是 `minmax(0, 1fr)` 等宽，所以**棋盘永远落在屏幕正中间**
（实测水平偏差 0px）；侧栏内容再用 `max-width` 收窄，免得宽屏上被拉成一条。

**二、每个尺寸都给了横向和纵向的上限。**

| 变量 | 上限怎么来的 | 少了这一项会怎样 |
| --- | --- | --- |
| `--cell-w` | `100vw - 两侧栏 - 栏间距 28 - 内边距 40 - 格子之间的 7 个 gap 56` | 地图宽 = `8*格子 + 7*gap`，只减 68 的话格子接近上限时地图会宽出 56px，挤到侧栏上 |
| `--side-w` | `min(306px, 19vw)` | 固定 306px 时，1024 宽的窗口里两栏吃掉 612px，格子只剩 36px |
| `--shop-card` | `min(152px, (100vw - 310px) / 5)` | 5 张卡 + 4 个 gap + 操作列 196 + 内边距 40 = `5*卡宽 + 308`，窄窗口下商店横着溢出去 |
| `--arena-h` | `(100vh - 136px) / 8` | 战场要放 8 行；不设这条的话窄高屏上画布放不下、出滚动条 |
| `--arena-w` | `(100vw - 144px - 战报栏 - 左栏) / 8` | 同上，横向版 |

### ★ 战场 = 布阵盘的 2 倍，而且是同一把尺子

这是「**布阵时怎么摆、打起来就在哪**」的实现方式。

两边**共用同一个 `--cell` 和同一个 `--gap`**，画布的定位步长是
`pitch = 格子 + 间距`（不是格子大小）。于是：

| | 布阵盘 | 战场 |
| --- | --- | --- |
| 列数 × 行数 | 8 × 4 | 8 × 8 |
| 宽 | `8格 + 7间距` | `8格 + 7间距`（**完全相同**） |
| 高 | `4格 + 3间距` | `8格 + 7间距`（≈ **2 倍**） |
| 第 c 列中心 | `c × pitch + 格/2` | `c × pitch + 格/2`（**逐列重合**） |
| 我方 4 行 | — | 布阵盘整块下移 `4 × pitch` |

实测（8 种分辨率、每次 8 个棋子逐格比）：**列偏差 0.00px、行偏差 0.00px**。
战场宽度和布阵盘宽度逐像素相同，高度比 2.016 ~ 2.029。

这里踩过两个坑，都很隐蔽：

1. **画布把 `CELL` 同时当成了格子大小和间距。**
   布阵盘第 c 列中心 = `c × (格 + 间距) + 格/2`，
   而画布算的是 `c × 格 + 格/2` —— **每列少 8px，8 列累计 56px**。
   阵型一开战就被横向压扁一点点，看起来「差不多但就是不对」。
2. **`--cell` 是 `min(...)` 算出来的小数**（比如 85.6）。
   画布是位图、格子必须取整，但如果**只让画布取整**、布阵盘还按 85.6 排版，
   两边每列又差 0.6px。所以 `arena.js` 算出整数后写回 `--cell-r`，
   **两边共用同一个整数**（`--cell` 本身不能覆盖，它是「意图值」，覆盖掉就再也算不回来）。

涨起来的办法也不是「把数字调大」，而是**把播放条挪走**：
它原来压在画布下面白占 65px，而左右两侧本来就有富余的横向空间。
（和准备阶段同一个思路：**先把浪费掉的空间找回来，再谈放大**。）
画布不再有单独的档位 —— 8 行 / 8 列这两条上限已经并进 `--cell` 的 `min()`，
屏幕什么形状都不用再枚举档位。

| 分辨率 | 格子 | 布阵盘 | 战场 |
| --- | --- | --- | --- |
| 1024×768 | 63 | 560×276 | 560×560 |
| 1280×720 | 67 | 592×292 | 592×592 |
| 1366×768 | 79 | 688×340 | 688×688 |
| 1440×900 | 95 | 816×404 | 816×816 |
| 1600×900 | 95 | 816×404 | 816×816 |
| 1920×1080 | 118 | 1000×496 | 1000×1000 |
| 2560×1440 | 120 | 1016×504 | 1016×1016 |

**画布格子必须向下取整。** 8 个格子每个多 0.5px 就是 4px ——
1440 宽的屏上画布正好因此比预算宽 4px，战斗界面直接出横向滚动条。
（`readCell()` 里那句 `Math.floor` 是踩过一次才改的。）

**canvas 的边框要用 `box-shadow` 画，不能用 `border`。**
画布的元素宽度是内联设的，如果再有一条 1px border，在 `box-sizing: border-box`
下内容盒变成 `w-2`，浏览器会把整张位图缩到 `w-2` 里显示 ——
画布上的一切都被缩了 0.2%，「布阵怎么摆、打起来在哪」就不成立了。

### 讲话石：一次「垫底装备」是怎么被机制救回来的

原名叫「荆棘之甲」，效果是「反弹承受**物理**伤害的 32%」，而且**只反弹给打它的那一个**。
对位循环赛里它一直垫底（**43.6%**）—— 试过把比例从 20% 提到 32%，排名没动，
说明这**不是数值问题**：收益面本身就窄（对面一套法术阵容就完全失效）。

改成 **讲话石** 之后（改名 + 换图标 + 改机制）：

```
受到伤害 → 对 3×3 范围内所有敌人反弹该伤害的 32%
```

改后的技能叫 **【飞入寻常百姓家】**（名字写在 `items.js` 的 `skill.name` 里，
和数值说明 `desc` 分开 —— 以后调数值不用动技能名）。

| 改动 | 为什么 |
| --- | --- |
| 单体重弹 → **3×3 范围** | 一次性惩罚一整片贴身的人，而不是只惩罚出手的那一个 |
| 只算物理 → **任何伤害** | 法术阵容不再能让它完全失效 |
| 反弹仍是 `true` 伤害 | 不该被对面的护甲/魔抗再削一次 |
| 加了**河水特效** | 见下 |

结果：对位胜率 **43.6% → 68.9%**，从垫底升到第 3。

**水系特效**（`arena.js` 的 `addRiver` / `addRipple`，由 `reason === 'thorn'` 触发）：

* `river` —— 一条从佩戴者流向受害者的**水带**：三层粗细/透明度不同的曲线叠出水感，
  前端只画到「已经流到哪」（像水正冲过去），后面跟一撮水花
* `ripple` —— 地面上的一圈**水波**，压扁成椭圆（`ry = rx × 0.40`）：
  正圆看着像光环，扁的才像地面上的水面
* 伤害数字换成水色（`thornWater`），和普通反伤的暖红一眼分开

★ 一次受击会同时弹到九宫格里所有人（最多 9 个），所以水带必须**细、快、半透明** ——
九条粗线同时出现就成一团糊了。特效寿命只有 0.40 秒，也不需要额外限流。

**技能名在界面上出现的位置**：装备栏 tooltip、选中装备的面板、选中棋子的「装备」那一行、
掉落弹窗、装上去的回合记录。战斗回放里**一局只播报一次**「🌊【飞入寻常百姓家】X 的讲话石开始还手」——
后面每次反弹都有水带看得见，文字再喊一遍就是刷屏。

实现上有两个容易写错的点：

1. **反弹可能打死人，必须自己判一次死亡。** 原来只弹给攻击者，
   那次死亡由 `afterDamage` 末尾统一的 `checkDeath(src)` 兜住了；
   现在受害者可能不是攻击者，漏掉就会留下「血量 0 但还活着」的僵尸。
2. **反弹不会再触发一次 `afterDamage`** —— 所以两个人各带一块讲话石
   也不会互相弹到天荒地老。

* `frenzy` 上限 **+200%**（3 倍出手速度），**永不衰减** —— 换目标、被眩晕都不清零。

  回血量会被剩余血量空间截断，所以每次回血 = `min(最大生命 × 比例, 剩余空间)`。
* `healGift` 是**限时可刷新**的（4 秒），不是本局永久 —— 见下面「豆包」那一节。
* `snipeSure` / `clawGuard` 的 `perHit` 装的是**次数**而不是百分比 ——
  这两个在 `game.js` 里**不能无脑 ×100**，否则会显示成「必定命中 100 次」。
* `crash` 是**唯一一个「死后才生效」**的被动，也是唯一一个三层**叠加**的
  （3★ = 1★ 的坠机 + 2★ 的复活 + 自己的冷却减半）—— 见下面「牢大」那一节。
* `clawGuard` 是**唯一一个拦在伤害管线最前面**的被动 —— 见下面「鸭子」那一节。
* `overclock` 是**唯一一个会改单位移速**（往上加）、也是唯一一个**没有上限**的被动 ——
  它是"限时超频"：开局猛，约 25 秒后开始自毁。见下面「张雪峰」那一节。
* `laugh` 是**唯一一个不动数值、只开门槛**的被动 ——
  它的三层改的都是「大笑」这**同一个状态**（`moveAt: 2` / `healAt: 3` 两个开关），
  所以 `perHit` 全是 1，真实门槛在 `moveAt` / `healAt` 上。
  文案也因此不能逐层列数值，只能写"这一星级多出了什么"。
  见下面「奶龙」那一节。
* `domain` 是**唯一一个改「技能本身参数」**的被动 ——
  前面八个都是"触发时额外做点什么"，只有它改的是"这个技能一次打几个、控多久"。
  所以它的 `perHit` 是 **0/1/1**（纯粹当"这一星级有没有被动"的开关用），
  真正的数字在 `targets` / `durMul` 里，**拿去 ×100 就会写出「一次控 100 个人」**。
  见下面「嘉豪」那一节。
* `peak` 是**唯一一个「技能只负责给自己上 buff、伤害走下一次普攻」**的被动，
  也是目前唯一一个**一个 kind 挂两件互不相关的事**（2 星改"打出去之后发生什么"、
  3 星改"它自己死的时候发生什么"）。它的 `perHit` 同样是 **0/1/1** 当开关用，
  真数字在 `stunDur`（3 秒）/ `boomAdMult`（×20）里。
  见下面「羊帆」那一节。
* `field` 是**唯一一个把效果留在场上、而不是挂在人身上**的被动 ——
  它背后是游戏里第一份**不属于任何单位**的持续状态（`st.fields`）。
  前面十种效果人一死就跟着没了，领域不一样：施法者死了它照样下雨。
  见下面「楚生疑犯」那一节。
* `loneWolf` 是**唯一一个会碰"法力怎么涨"这条规则**的被动 ——
  其余十一种都在"伤害 / 攻速 / 控制 / 地形"里打转。
  它也是目前唯一一个**三层各管一件事、互不相干**的被动
  （绝境 / 开局 / 续航）。见下面「Dank1ng」那一节。
  ★ 它顺带逼出了两个新东西：`CFG.CAST_LOCK`（施法节流）和
    `death` 事件里的 `by`（击杀者）。

**★ 按次数回血的强度特征**（实测，同一个对手单挑）：

```
对手单次伤害          3★ 狼王每次回血   等效减伤
45  （1★ 荣誉）     80               >100%  —— 打不死
146 （3★ 荣誉）     80               55%    —— 1★/2★ 都阵亡，它活下来
345 （3★ 张雪峰）       80               23%
```

也就是说：**对手单次伤害越低，这个被动越离谱**（小刀流/多段伤害几乎打不动它），
面对重击则只是个不错的续航。以后调平衡时要盯的是「攻速快 + 单下低」的组合，
而不是面板总输出。

数据写在 `js/units.js` 的 `passive` 字段里，规则在 `js/battle.js`：
`frenzy` 在 `attackOnce` 之后叠层，`hurtHeal` 在 `afterDamage` 里回血，
`healGift` 在 `healUnit` 里——**写完 heal 事件之后**才触发。

数据写在 js/units.js 的 passive 字段里，规则实现在 js/battle.js 的
gainFrenzy()。三个刻意的设计选择：

1. **加在伤害结算之后** —— 第 N 次攻击吃的是前 N-1 层的加成，
   不存在「打出去的那一下同时被自己的触发加强」这种循环。
2. **永不衰减**：换目标、被眩晕、走位都不清零。
   玩家看到的是一条只涨不跌的曲线，不需要猜「什么时候会掉」。
3. **到上限就不再写事件** —— 否则后期每一下普攻都白写一条日志。

和技能给的攻速 buff（战意 / 疾风连斩）是**加法**叠加，不是连乘 ——
连乘会让「+90% 的连斩」和「+200% 的愤怒」互相放大到离谱。

**可见性**（数值在模拟器里，但看不见就等于没有）：

* 选中面板：生效时显示琥珀色徽章「⚡ 极度愤怒：每次攻击攻速 +10%…」；
  1 星时显示解锁预告「☆ 被动预览：2 星「更加愤怒」…」
* 战斗画布：卡牌左下角常驻「⚡+35%」，每叠一层闪一下白；
  卡片外圈一圈琥珀色发光，亮度跟着层数涨；叠满时变亮橙
* 上限到顶时给一次扩散环，让「封顶了」这件事有反馈

★ 加新角色只要在自己的 `units.js` 条目里写一段 `passive` ——
`battle.js` 是按 `kind` 分派的（`frenzy` / `hurtHeal` / `healGift` / `snipeSure` / `crash`），
加新种类不用动 `buildSide`，但要在三处一起补：
`battle.js` 的触发点、`game.js` 的 `passiveLine`/`passiveTeaser` 文案、
`simtest.js` 事件校验器里的新 case。

同名规则补充：`passive.names[star]` **允许写数组**（牢大 3★ 是两个被动叠在一起），
`passiveName()` 会用 ` + ` 连起来，界面那边什么都不用改。

### 豆包（原「修女」）：幻觉 / 开智

`修女` 改名 **豆包**（id 仍然是 `acolyte` —— `levels.js` 的 8 处阵容、
tests 断言、`art/acolyte.png` 全部按 id 索引，改名一个字都没动 id），
立绘换成 `art/acolyte.png`。

| | 触发 | 结果 |
| --- | --- | --- |
| **幻觉**（2★） | 每奶出一口**有效**治疗 | 掷一次骰子：50% 增伤 20%，50% **减伤 20%** |
| **开智**（3★） | 同上 | 不掷骰子，**必定增伤 20%** |

四个刻意的设计选择：

1. **限时 4 秒、可刷新，不是本局永久。**
   被动写的是「每次治疗有 50% 概率」。如果效果永久，多奶几口之后
   必定会掷出一次增伤，之后每口奶都不再有意义 ——「50%」就退化成了
   「前几秒的随机启动时间」。做成限时的，每一次治疗才都真的是一次重新掷骰子。
2. **增伤和减伤是同一个骰子的两个面**，不是两次独立判定。
   这正是「幻觉」的意思：她分不清自己在帮谁。
3. **3 星的收益是「必定成功」，不是数字变大。** 2★/3★ 的幅度都是 20% ——
   升级买的是确定性。所以在自检里这一条是**硬断言**：
   3★ 整场出现一次减伤就算失败（实测 24 场 68 次赠礼，减伤 0 次）。
4. **触发条件是「真的回了血」**（`real > 0`），不是「放了治疗技能」：
   一口被 `healPool` 攒住的奶（不足 1 点）或者奶在满血的人身上，
   实际上什么都没发生，不该白送一次被动。

**倍率乘在哪里**：`dealDamage` 里的 `raw × boost × ramp`，乘在**出手方的原始伤害**上，
而不是去改对方的护甲 —— 改护甲会被「真实伤害无视护甲」这类规则绕过去。
讲话石的反弹也走这条路（`src` 就是佩戴者），所以「被幻觉误导的人连反弹都变弱」
是自洽的，不需要额外特判。

**可见性**（这一层是渲染层的责任）：

* 画布上挂上的一瞬间：金环 + 金色飘字「增伤」／紫环 + 紫色飘字「减伤」，
  冷暖两色一眼分好坏
* 卡片**费用徽章正下方**常驻 `↑+20%`（金）/ `↓-20%`（紫）。
  ★ 必须有这个持续标记：挂上去那一下是瞬时的，但效果要挂 4 秒 ——
  只有飘字的话，玩家看到「增伤」飘走之后，接下来 4 秒里根本不知道谁身上还有状态。
  到期靠**时间戳自然失效**（`st.t < buffUntil`），不需要「到期」事件，
  渲染层也不需要每 tick 去扫。
* 战斗回放：**只在结果翻转时播报**（第一次一定写，让玩家知道这个被动存在）。
  每次治疗都写一条的话，一个奶妈一局能刷几十行。

**实测数据**（24 个固定种子，`acolyte` 带 3 块蓝水晶单挑 1★ 100元的鸭子）：

```
2★  赠礼 72 次（增伤 38 / 减伤 34，增伤占比 53%）
    非暴击普攻 720 次，其中身上带效果出手 115 次
    raw ÷ (ad × ramp) 的分布：{1: 605, 1.2: 61, 0.8: 54}
3★  赠礼 68 次（增伤 68 / 减伤 0）
    raw ÷ (ad × ramp) 的分布：{1: 536, 1.2: 87}
```

第二张分布表是这次改动里**唯一能直接证明「倍率真的乘进了伤害」**的东西 ——
只看 `gift` 事件只能证明状态挂上去了，证明不了它起作用。
它同时也是那条最有力的断言：出手伤害的倍率**只可能是 1 / 1.2 / 0.8 三种**，
出现第四种就说明有别的乘法在偷偷叠加。

★ 测试场景在这里踩过一次坑（已记进下面的踩坑表）：一开始摆的是
「3 星铁壁 + 豆包 vs 剑客」，看着合理，实测 25 秒里 11 次施法只落地 1 次治疗 ——
`lowestAlly` 只奶**血量百分比最低的队友**，铁壁一死她就只能奶自己，
满血时那一口被 `healUnit` 直接丢掉（`room < 1` → 不写日志、不触发被动）。
7 条断言全红，看着像机制没生效，其实是场景选错。

### 荣誉（原「短弓手」）：狙击1

`短弓手` 改名 **荣誉**（id 仍然是 `bowman` —— `levels.js` 的 30 多处阵容、
tests 断言、`art/bowman.png` 全部按 id 索引），立绘换成 `art/bowman.png`。

面板改成了**慢枪手**：

| | 改动前 | 改动后 |
| --- | --- | --- |
| 攻击力 | 45 | **90**（翻倍） |
| 攻速 | 0.68 | **0.34**（减半） |
| 面板 DPS | 30.6 | 30.6（**一点没变**） |

★ 这两个数字必须**成对**出现。只翻倍不减半就是白送一倍输出；
自检里专门有一条断言把「改动前 DPS == 改动后 DPS」钉住，
因为单看「ad 应该是 90」根本看不出翻倍和减半是配套的。

技能从「穿心箭」（`nuke`，200 点必中）换成 **「狙击1」**：

| | |
| --- | --- |
| 命中率 | **20%** |
| 命中伤害 | 基准 200 **× 10**，再走正常的法强 / 减伤 / 递增 |
| **收费方式** | **不吃法力**：开局立刻白送一发，之后**每 3 次普攻**攒一发 |
| **蓄力** | 攒满后先站定 **0.5 秒**，双眼喷金色激光，然后才开枪 |
| 2★ **运** | 每局第 1 次狙击**跳过掷骰子，直接命中** |
| 3★ **edg希望** | 每局前 2 次必定命中 |

四个实现上的选择：

1. **`snipe` 事件写在伤害之前**，事件顺序是 `charge → cast → snipe →（命中才有）skill`。
   这样回放才是「先看到激光、再喊 Vamos / Kale、最后是伤害数字」——
   反过来就成了先掉血再喊，很怪。代价是 `snipe` 事件里没有 `dmg` 字段，
   命中的伤害在紧跟的 `skill` 事件里；校验器就是靠
   「`hit=true` 后面必须紧跟一条同 tick、同起止的 `skill`」来验的。
2. **打偏必须一分血都不掉**，而且校验器会反过来验「没命中就不许有那条 skill 事件」。
   只在渲染层表现 miss、规则层偷偷扣血，是这个机制最容易出的假动作。
3. **保底不消耗随机数**：还有「必定命中」次数就直接命中并扣一次。
   所以 3★ 和 1★ 在同一颗种子上会走出**不同的 RNG 序列** ——
   这是正确的（它们本来就是不同的棋子状态），但意味着给某关敌人换个星级，
   会让那一关的整段回放重排。
4. **蓄力那 0.5 秒是规则，不是特效。** 蓄力期间棋子站着不动、不出手 ——
   所以这一枪是**被预告过的**。`CFG.CHARGE_TIME` 同时决定了
   渲染层那条激光的寿命：激光消失的那一帧，子弹正好出膛。
   要调这个数就调 CFG，不要在渲染层单独改。

### 为什么要从「法力」改成「攻击计数」

荣誉的攻速被砍到了 0.34（单次伤害翻倍换来的），于是：

```
走法力（法力 60，每次普攻 +10）：6 次普攻 = 17.6 秒 → 一局最多 2 次技能
走计数（每 3 次普攻一发）：      3 次普攻 = 8.8 秒 → 一局最多 4~7 次技能
```

走法力那版实测下来，荣誉**一局只放得出 1~2 次技能**，
20% 的命中判定基本轮不到发生，「前两次必定命中」的保底更是永远用不完 ——
**整个机制等于白写**。改成计数之后才真的像一个「慢枪手」：
平时憋着，每三下还你一炮。

★ 法力条没有被浪费掉：计数型棋子的 `mana` 被改写成
`maxMana × (已普攻次数 / 3)`，**原来那条法力条直接变成「狙击充能条」**，
满格就是要开枪了。不用为一个新机制再动一次界面。

★ 这条规则的数据在 `units.js` 的 `skill.cast`：`{ opening: true, perAttacks: 3 }`。
`battle.js` 里 `tryCast` 按「有没有 `cast` 字段」分岔，
有 `cast` 的棋子 `gainMana` 直接返回（完全不吃法力）。
自检里有一条专门盯着「目前只有荣誉是计数型技能」，免得哪天误伤别的棋子。

**可见性**：

* **字幕**：射手卡牌**正上方**弹出
  * 命中 **Vamos**（金 `#ffe07a`），打偏 **Kale**（灰蓝 `#9fb0bd`），
    走保底的那几发是**青色 Vamos** `#7ef0d8` —— 让「这发是运，不是运气」看得出来
  * 字号 **CELL × 0.62**（95px 格子上约 59px，「Vamos」横过去约 1.6 张卡牌宽），
    外加**半透明深色圆角底板 + 同色描边 + 同色外发光**，停留 1.45 秒
  * 弹出用 easeOutBack（0.4 → 1.0，中途冲过一点再收回），
    不透明度前端 6% 淡入、末尾 25% 淡出，**中间一大段是完全实心的**
* **眼睛喷金色激光**（蓄力的那一整段）：两只眼睛各一道 `#ffe07a` 光束指向目标，
  越蓄越粗越亮（亮度走 `p^1.7` 而不是线性 —— 线性的话前半段就已经很亮，
  看起来像「一直在射」而不是「在攒」），最后 12% 再补一圈闪光作为「蓄满了」的信号。
  眼睛位置是从卡面**估**出来的（上方三分之一、左右各偏 16% 卡宽），
  换立绘如果眼睛位置差得多，改这两个系数就行
* **弹道**：五层叠出来的一条光（`40px 氛围 / 26px 大光晕 / 13px 光晕 / 6px 实心彩线 / 2.6px 白热芯`），
  生命 0.30 秒且**前 55% 一点都不衰减**
* **枪口闪光**：开枪瞬间从枪口炸开的一圈光环 + 四道十字亮线 ——
  它回答的是「这一枪是从谁那儿打出来的」，混战里没它就看不出弹道来源
* 命中额外给顿帧 0.10s + 震屏 11，打偏则在目标旁边留一小撮「擦过去」的灰白气流
* **打偏的时候子弹不是消失，而是继续飞出去**（越过目标 2.2 个格子），
  否则 miss 和「什么都没发生」看不出区别

★★ **字幕是所有角色的公共设施，不是荣誉专用的。**
以后再加「打中了喊一句」的角色，一律调 `arena.js` 里的 `addCallout(x, y, text, color)`，
字号、底板、弹出动画、停留时长就都是同一套 —— 不要各写一份，
否则每个角色的台词会长得不一样，而且很容易有人写小了没人发现。

★ 这一轮为什么会改：上一版弹道是 5px 光带、字幕是 CELL×0.30（95px 格子上约 28px），
**实测在战场上根本看不清**。而当时**纯数值自检全绿**（数值一点没错）——
是肉眼反馈才发现的问题。所以现在把「够不够大」也变成了断言：
`gametest` 会真的跑一场、从 `Arena.fxList()` 里捞出字幕，
断言 `字号 >= 格子 × 0.55`、`停留 >= 1.2s`、`保底命中是青色`。
以后谁把字号改回去，自检会红。

**实测数据**（自检里跑出来的，不是估算）：

```
1★  60 场 1v1：开枪 108 次，命中 20 次 → 命中率 19%
2★  40 场：每局第一枪必定命中；保底用完之后的 35 枪命中 8 次（23%）
3★  40 场：每局两枪，两枪都必定命中；单局最多用掉 2 次保底
装填节奏：核对了 96 枪 —— 开局那枪在 0 次普攻时打出，
          之后第 k 枪全部正好落在第 3(k-1) 次普攻之后
蓄力：    96 枪 / 96 次蓄力，一一对应
装填的余地：单局最多 2~4 枪（攻速 0.34 ⇒ 每 3 次普攻要 8.8 秒）
```

第二、三行是这次改动最想看见的东西：**保底用完之后的枪真的回到了 20%**
（23%，样本 35），而不是偷偷全都命中 —— 那正是「运」和「edg希望」值钱的原因。

★ 平衡影响（`balancetest` 的原话）：
**1 费档内最强从别的位置换成了荣誉 27.0%**。
这是「每 3 次普攻一发」+「开局白送一发」的直接结果 ——
一局的开枪次数从 1~2 涨到 2~4，期望输出差不多翻倍。

★★ **这一节记录的是改动前的旧结论，现在已经被「攻击计数」解决了。**
留在这里是因为它是那次改动的全部理由 —— 一个**概率型机制如果轮不到触发，
概率就只是个装饰**：

改动前的收费方式是法力 60 + 每普攻 +10，而攻速是 0.34，于是：

* 6 次普攻 = 17.6 秒 ⇒ 一局**最多放 2 次技能**
* 团战里荣誉 500/900 血常常**一枪都开不出来**就先被打死了
* 结果：3★ 的「前两次必定命中」等于整场必中，

改成「开局一发 + 每 3 次普攻一发」之后：
3 次普攻 = 8.8 秒 ⇒ 一局最多 4~7 枪，
而且**第一枪在 t≈0.5 秒就出去了**，不会再有「一枪没开就死」。
实测 2★ 保底用完之后的 35 枪命中率回到 23%，这个赌局才真的在发生。

### 牢大（原「蛮牛」）：肘击 / 坠机

`蛮牛` 改名 **牢大**（id 仍然是 `brute`），立绘换成 `art/brute.png`。

**技能「肘击」**：从「蛮力冲撞」（`line`，打一整条线）换成
`knockback` —— 单目标 440 法术伤害 + **击退 2 格**，并且喊一句 **Man！**

击退有三个刻意的设计选择：

1. **方向只取一个主轴**（行、列差值大的那一边），不斜着推。
   斜推两格在切比雪夫距离上是 2、在曼哈顿距离上是 4，玩家会觉得"怎么飞这么远"。
2. **撞到棋盘边缘或任何人就停**，不做「挤开别人」的连锁 ——
   这样占位表永远不需要处理重叠。推不动（0 格）时**根本不写事件**，
   不留空动作。
3. **先结算伤害、再击退**，而且施法者死了就不推了。
   顺序反过来的话，目标可能在被打飞的路上就死了，伤害还要回去找它的位置；
   而「牢大肘出去的同时被讲话石弹死」是完全可能的（`skillDamage` 里就会触发反伤）。

**被动「坠机」—— 三层叠加，不是替换：**

| 星级 | 效果 |
| --- | --- |
| 1★ | **坠机**：阵亡 1 秒后直升机坠毁，对 3×3 范围内的敌人造成 900 点物理伤害 |
| 2★ | + **孩子们我回来了**：坠毁之后原地复活（半血），**一局只给一次** |
| 3★ | + **曼巴精神**：复活之后技能所需法力减半 |

五件必须说清楚的事：

1. ★★ **「倒地但没结算完」不参与胜负判定。**
   主循环原来在 `aliveCount === 0` 时立刻结束 —— 牢大会先被判成全灭，
   直升机永远落不了地、也永远复活不了。现在多了一个 `anyPending()`：
   只要还有单位「倒下了但 `downUntil` 还没到」，这一方就还没输。
   这是整套被动唯一需要主循环配合的地方，也是它最容易被写漏的地方。
2. **一局只复活一次，但坠机每次都打。**
   上限写在 `passive.maxRevives`（= 1），不是硬编码在逻辑里。
   次数用完之后**坠机照打、只是不再站起来** —— 坠机是 1★ 就有的被动，
   不该跟着复活的次数一起消失。所以第二次阵亡的表现是：
   倒下 → 1 秒 → 直升机落地 → 就此退场。
   `down` 事件里的 `revive` 字段是**这一次还会不会站起来**（不是"有没有这个被动"），
   用完了就如实写 `false`，界面据此决定要不要画"还会站起来"的暗示。
3. **先炸、再复活。** 复活的牢大站在自己刚砸出来的坑上是安全的
   （坠机只打敌人），但反过来先复活再结算伤害，它就会被自己的爆炸打一下 ——
   那不是设计意图，是顺序问题。
4. **「CD -50%」在没有冷却的游戏里 = 技能所需法力减半。**
   这个游戏的法力就是冷却，所以 3★ 复活后 `maxMana` 砍半，出手频率翻倍。
   事件里带 `cdCut` / `maxMana` 两个字段，界面据此显示。
5. ★ **伤害类型是物理，不是真实伤害 —— 这是量出来的，不是随手写的。**
   一开始用的是真实伤害（"环境伤害不该被护甲挡住"，听着很顺），
   结果 levelcurve 直接报「20 关太水 +74%、21 关 +36%、22 关 +52%」：
   900 点无视防御的伤害刚好卡在那些关卡敌人血量的门槛上，一砸一片，
   难度余量出现断崖。换成物理（吃护甲）之后同一条曲线变成
   20 关 +12%、21 关 +19%、22 关 +35%，后半程重新比前半程更紧。
   物理也更合理：被一架直升机砸中是实打实的撞击，该吃护甲；
   「无视防御」留给讲话石那种「你打我我就原样还你」的机制。

★ **「击退 + 复活」在单挑里会制造僵局**：两个 2★ 牢大互相肘飞、
又各复活一次，谁也打不死谁 —— 实测 120 场镜像单挑里有 **76 场打成平局**
（靠 60 秒超时按血量比判，两边血量一样就是平）。这不是 bug，
但这个组合的性格就是这样，配阵容时值得记一笔。

★ 顺带修掉一个**先手公平性**的坑：`freeCellNear` 给复活找落点时，
第一版只按 (切比雪夫, 曼哈顿) 排序、平局按行号小的优先 ——
于是 A 方总是复活在自己半场**后排**、B 方总是复活在**前排**
（B 的半场行号大），镜像对局的胜率直接变成 61%:39%。
第三关键字换成 `mirrorTie`（和寻路定序同一套规则）之后才对称。

### 角色台词（字幕）
`arena.js` 的 `addCallout(x, y, text, color)` 是**所有角色台词统一的入口**。

* **数据侧不用碰渲染层**：技能里写一行 `callout: 'Man！'`，
  `cast` 事件会把它带出来，渲染层自动弹字幕。荣誉的 Vamos / Kale 走的是
  同一套函数（它在 `snipe` 事件里调）。
* **字幕只有字，没有底板**：厚深色描边勾轮廓 + 亮色填充，字号 CELL × 0.62。
  上一版是一块深色圆角牌子 + 彩色描边，清楚但像贴了一张 UI 组件；
  去掉之后压在什么画面上都还是"一行喊出来的话"。
  ★ 这一条有像素断言守着：`gametest` 会截喊话刚出现的那一帧，
  量那块矩形里**深色像素的占比** —— 有底板时约 80%，只有字时是 1%。

### 100元的鸭子（原「铁壁」）：抓娃娃

`铁壁` 改名 **100元的鸭子**（id 仍然是 `ironwall`），立绘换成 `art/ironwall.png`。

**血量砍到十分之一：950 → 95。**
不是笔误 —— 它的全部生存能力都押在被动上，所以它是一张**次数盾**：
次数没耗完时它是一堵墙，耗完的那一瞬间它就没了。
血量必须低到这个程度，否则「次数盾 + 正常血量」会变成一个打不死的坦克。
（注意星级的 1.8× / 3.24× 仍然照常作用：1★ 95、2★ 171、3★ 308。）

**被动「抓娃娃」**：敌人打过来的**前 N 次伤害判定直接无效**
（1★ 20 次 / 2★ 30 次 / 3★ 40 次）。

三个实现上的选择：

1. ★★ **拦在 `dealDamage` 的第一个岔口上** —— 在所有计算之前、也在扣血扣盾之前。
   放到 `afterDamage` 里就晚了：那时候血已经掉了、盾已经被吃掉了，
   只能再补回来，日志里会出现「掉一下血又回一下」的假象，
   而且「hpLoss 必须等于血量差」这条校验立刻会炸。
2. **返回值里的 `effective` 仍然是"本该打出多少"**（不是 0）。
   日志里 `attack` 事件的 `raw` 字段用的就是它，意思是
   "这一下本来能打这么多，被挡了"。这样「raw >= dmg」和
   「倍率只能是 1 / 1.2 / 0.8」两条断言都还成立。
3. **计数是总次数**，不区分是谁打的、也不区分普攻和技能 ——
   「敌人前 N 次攻击无法对其造成伤害」按字面就是这个意思。
   想改成「只挡普攻」，在 `dealDamage` 里加一个 `kind` 过滤即可。

**可见性**（它只有 95 血，玩家必须能看出"还挡得住"还是"快没了"）：

* 卡片**费用徽章正下方**常驻 `🛡N` —— 剩余次数，挨一下减一、同时闪白
* 挡下的那一下：青色护盾环 + 一小撮火星 + 一个「挡」字飘出来，
  **没有任何伤害数字**（因为真的一分血都没掉）
* 战斗回放只在 **剩 10 / 剩 5 / 用完** 三个时刻各写一行。
  一局能挡 20~40 次，每次都写会把回放刷爆

★ 自检里那两条「挡伤」断言值得单独说：`simtest` 会核对
**窗口内每一次挨打的 `dmg` / `hpLoss` / `shieldLoss` 全是 0**。
只判血量是不够的 —— 鸭子自己会开 380 的护盾（钢铁壁垒），
一个护盾能替它扛十几下，只盯血量的测试完全察觉不到。

### 张雪峰（原「剑圣」）：超频 / 巧乐兹 / 雪毙

`剑圣` 改名 **张雪峰**（id 仍然是 `blademaster`），立绘换成 `art/blademaster.png`。
技能「万剑归宗」保持不变。

**1★「你快不过我你信吗」**：

| | |
| --- | --- |
| 开局 | 攻速 **+100%**、移速 **+100%** |
| 每次普攻 | 攻速再 **+2%**，**没有上限** |
| 攻速加成到 **+200%** | 之后**每秒失去当前生命的 44%**（自毁） |
| 普攻 | 1/2 星是**单体** |

**2★「巧乐兹」**：每次普攻打到的敌人各 +1 层**冰棍**，
每层 **-5% 攻速 / -5% 移速**；**满 10 层冰冻 3 秒并清空层数**。

**3★「雪毙」**：攻速加成到 +200% 之后，**攻击力 +78%**；
同时**普攻升级成 3×3 范围**（1/2 星是单体）。

★ 为什么范围放在 3 星：他是"限时超频"型角色，1 星就该只有"出手快"
这一个爽点；3×3 是升到 3 星之后拿到的**质变**，和雪毙的 +78% 攻击力一起，
把"超频"从"打得快"变成"打得快而且打一片"。
数据上就是 `passive.ocAoeAt: 3` 这一个门槛 ——
和 `chillAt` / `ocAdAt` 一样，星级门槛全部写在数据里，不散在逻辑里。
**自检是正反两面都验的**：1/2 星必须一条溅射都没有，3 星必须有。

五个实现上的判断：

1. ★★ **「攻速达到 200%」算的是"加成"，不是"每秒攻击 2 次"。**
   和「愤怒的普通人」那句「上限 +200%」是同一套口径（+200% = 三倍出手速度）。
   按后一种算的话，0.88 的基础攻速只要 6 次普攻就触发自毁，
   这个角色活不过 5 秒 —— 数字一样，含义差了一个数量级。
2. **这是一个"限时超频"的设计**：开局比别人快一倍，约 50 次普攻（≈23 秒）后
   开始烧自己，44%/秒的**当前**生命衰减意味着还能撑两三秒。
   所以它必须被做得足够强（5 费），否则就是一张自杀卡。
   用「当前生命」而不是最大生命也是这个原因：指数衰减，越到后面掉得越慢。
3. **自毁是"失去生命"而不是"受到伤害"**：不过护盾、不触发反伤、
   也不会被鸭子的「抓娃娃」挡掉（那不是"敌人攻击"）。
   所以它直接改 `hp` 并自己 `checkDeath`，不走 `dealDamage`。
   `loss` 有 0.01 的下限 —— 不留下限的话血量会停在 0.01 永远死不了
   （round2 把 0.0044 变成 0），玩家会看到一个血皮不死的怪物。
4. **移速是这个游戏里第一个会变的单位属性**（原来所有棋子都是 0.3 秒一格）。
   实现方式是给走位计时器乘一个倍率 `moveMul(u)`，
   不改 `MOVE_INTERVAL` 本身 —— 常量保持全局唯一，谁慢谁快都从自己身上读。
5. **冰棍的减速乘在最后，不并进攻速加成里。**
   攻速加成是加法叠的（这是本项目的约定），但"减速"作用在
   **对手现在的出手速度**上：对面叠了多少攻速都该被砍掉一半（10 层 = ×0.5）。
   并进加成里的话，对面加成越高这个减速越像没发生。下限保到 0.1 倍防卡死。

**可见性**：

* 卡片费用徽章下方三行徽章：`⚡+N%`（超频攻速，越线后变红）、`❄N/10`（冰棍）、`🛡N`
* **越线那一刻**弹出台词「你快不过我你信吗」+ 红环 + 震屏 ——
  这是整套被动里最重要的信号：从现在起他在烧自己的血。不喊出来的话，
  玩家只会看到自己的五费莫名掉血
* 自毁用**独立的红色伤害数字**（`kind: 'selfBurn'`），和"挨打"的白/黄一眼分得开
* 满 10 层冰冻时弹「冰冻」字幕 + 冰蓝大环
* 回放只在**越线 / 血掉到一半 / 层数过半**这几个里程碑各写一条，
  不然每秒一行会刷爆

### 奶龙（原「石卫」）：捧腹大笑 / 笑气护体 / 边走边笑 / 笑传四方

`石卫` 改名 **奶龙**（id 仍然是 `stoneguard`），立绘换成 `art/stoneguard.png`。
技能「石壁」换成 **「捧腹大笑」**。

| | |
| --- | --- |
| 冷却 | **13 秒**（不吃法力 —— 游戏里第一个**纯 CD 技能**） |
| 效果 | 立刻大笑 3 秒：**受到的伤害 -80%**、**每秒回复 10% 最大生命** |
| 代价 | 这 3 秒里**不能移动、不能攻击** |

星级被动三层，改的都是**同一个状态**（笑）：

| 星级 | 名字 | 多出了什么 |
| --- | --- | --- |
| 1★ | **笑气护体** | 就是技能本身：很抗揍，但动不了也打不了 |
| 2★ | **边走边笑** | 大笑期间**可以移动**（仍然**不能**攻击） |
| 3★ | **笑传四方** | 大笑期间**同时治疗 3×3 范围内的队友**（每人每秒 10% 各自最大生命） |

六个实现上的判断：

1. ★★ **这是第一个"不吃法力"的技能，走的是纯秒表冷却。**
   实现方式和荣誉的「计数型」是同一套分岔口：`skill.cast` 存在就绕开法力，
   区别只是把"攒普攻次数"换成"攒时间"（`cdSeconds` / `cdAcc`）。
   **技能开局就在转**，所以第一次大笑落在 t ≈ 13 秒 —— 想让它开局就放，
   在数据里写 `cast: { opening: true }` 即可（荣誉就是这么配的）。
2. ★ **冷却在 `cooldownTick()` 里按 tick 走，不塞进 `updateUnit`** ——
   `updateUnit` 会被眩晕 / 大笑提前 return（"笑的时候什么都不做"就是这个 return），
   冷却要是跟着它走，一个被冻住的奶龙会**永远放不出技能**。
   "不能动"和"冷却不走"是两件事，别写在一起。
3. ★ **-80% 乘在减抗之后，不是乘在 `effective` 上。**
   乘在 `effective` 上的话，日志里的 `raw` 就变成"减伤之后"的数，
   「`raw >= dmg`」和「倍率 = 1 / 1.2 / 0.8」这两条自检会一起失效。
   放在 `mitigated` 之后，`raw` 的含义仍然是"出手方本来能打多少"，
   而 `dmg / raw` 在两个窗口的比值恰好就是 0.2 —— 自检就是这么验的
   （不用知道 `reduce()` 的公式，减抗和 ramp 会自动约掉）。
   **到期靠比时间戳**（`laughUntil`），和 `buffUntil` 是同一个套路，
   不需要任何"结束"事件。
4. ★ **状态只记在 `laughUntil` 上，不动 `stunUntil`。**
   复用一个"不能动"的字段看起来省事，但两者语义完全不同：
   眩晕是**外来**的、要能叠加时长、要被"免疫"类效果拦；大笑是**自己的**、
   固定 3 秒、而且还带减伤和回血。混在一起之后，
   玩家看到徽章写着「眩晕」但其实是自己在笑，就没法改任何一边。
5. **回血走 `healUnit`，不直接改 `hp`。** 治疗量、溢出截断、日志记账
   全由它统一处理，`hpLoss` 必须等于血量差的那条自检才继续成立。
   ★ 顺带一个推论：**满血的队友不会产生任何 `laughAura` 事件**
   （`healUnit` 里 `room < 1` 直接返回）—— 测试场景如果拿 3★ 山岳当队友，
   它的 620 护盾会把伤害全吃掉、血量一直是满的，于是"3 星会治疗队友"
   会测成"一条都没有"。**给机制配场景时要先问"这个人挨得到打吗"。**
6. **回放里 `laugh` 每次都写，`laugh` / `laughAura` 的 `heal` 一条都不写。**
   一次大笑能刷出 3 条自己的 + 最多 24 条队友的持续回血，
   而这些数字加起来根本对不上任何人的伤害；把"减伤 80%、每秒 10%、
   3×3 队友"全部塞进 `laugh` 那一行就够了。

**可见性**：

* 大笑瞬间：金色扩散环 + 火星 + 台词**「捧腹大笑」**；
  3 星额外加一圈更大的绿环（"队友也被逗笑了"）
* ★★ **连续飘字**：这 3 秒里 😂 会**每 0.28 秒冒一颗**，一直冒到笑完为止。
  光环和台词都是"一瞬间"的东西，而这个状态要挂 3 秒 ——
  只放一帧特效的话，字飘走之后画面上只剩一条金色描边和一枚小徽章，
  在十几张卡牌的混战里基本等于看不见。"它一直在笑"必须靠**持续**的视觉表达
* 卡片描边：金色外圈，**跟着剩余时间呼吸**，最后半秒改快闪（提示"快醒了"）
* 卡片徽章：`😂N.Ns`，常驻显示还差几秒笑完
* **法力条在这里是冷却条**：`mana` 由渲染层按 `cdSeconds` 和"上次大笑的时刻"
  自己算（`cooldownTick` 每 1/30 秒发一条事件会把事件流灌爆）。
  所以 `battle.js` 里 `attack` 事件的 `manaAfter` 对纯 CD 棋子必须**原样报 `u.mana`**
  —— 报"设想法力型会加多少"的话，冷却条会在每次普攻时往上跳一格。
* 一次大笑只写一行回放：`😂【捧腹大笑】奶龙 笑得停不下来 3 秒：受到的伤害 -80%…`

### 嘉豪（原「藤蔓精」）：男人领域 / 两个男人 / 三个男人

`藤蔓精` 改名 **嘉豪**（id 仍然是 `vine`），立绘换成 `art/vine.png`。
技能改叫 **「男人领域」**，**效果一个字没动**（还是眩晕 1.2 秒 + 90 点法术伤害）。
加的是星级被动：

| 星级 | 名字 | 多出了什么 |
| --- | --- | --- |
| 1★ | — | 只控住锁定目标（和改名前完全一样） |
| 2★ | **两个男人** | 一次同时控 **2 个人** |
| 3★ | **三个男人** | 一次同时控 **3 个人**，并且**眩晕时间翻倍**（1.2 → 2.4 秒） |

**这是目前唯一一个「改技能本身参数」的被动。** 前面八个都是"触发时额外做点什么"
（叠攻速、回血、给标记），只有它改的是"这个技能一次打几个、控多久"。
四个实现上的判断：

1. ★ `targets` / `durMul` 在 `buildSide` 里按星级算好写进单位身上
   （`domainTargets` / `domainDurMul`），`castSkill` 直接读 ——
   **技能代码里一句星级判断都没有**。想让 2 星也翻倍，只在数据里加一行。
2. ★★ **第 0 位永远是引擎锁定的那个目标，它不参与排序。**
   全部按距离排的话，「男人领域」就悄悄变成了"控最近的那个"——
   1 星只有一个目标时结果恰好一样，2/3 星却会把玩家锁定的那个人挤到后面去，
   玩家看到的就是"技能打歪了"。多出来的位置才按
   （切比雪夫 → 曼哈顿 → 镜像定序）由近到远补。
   ★ 定序沿用寻路/复活那一套，是为了 A/B 镜像局面下挑出来的是镜像的那几个人 ——
   不然会凭空给某一方先手优势。
3. **顺序是「先把这一圈全打完，再统一结算眩晕」。** 反过来的话，
   第一个被控住的人身上带着 `stun` 事件、而后面的人还没挨打，
   回放读起来像打了两次。1 星只有一个目标，两种顺序的事件序列完全一样，
   所以改这个不会动到老行为。
4. ★ **多出来的人选「最近的 N-1 个」，不限射程，而且人数是"保证的"。**
   想过两种收窄方案，都不要：
   · 限定「目标周围一格」—— 目标落单时就只控得住 1 个，
     「3 星一次控 3 个」变成一句看运气的话；
   · 限定「施法者射程内」—— 那个跟"领域"没关系，只是把近战的范围攻击
     换了个名字。
   实际对局里这个选择几乎不可见：嘉豪是近战前排，攒满法力要挨 6 次普攻（≈10 秒），
   那时候它早就贴在人群里了，最近的 2~3 个本来就都在身边 ——
   只有打到残局追最后一个幸存者时才会出现"隔着半场把人拖进来"的画面，
   而那正好符合「领域」这个名字。**选择要写在文档里，不然下一个人会以为是 bug。**
5. ★ 一次控多人时**每个人各发一条 `stun` 事件**（渲染层靠 `to` 给每个人画特效），
   但每条事件都带着**完整名单** `targets`，回放靠 `targets[0]` 判断
   "这是不是本次施法的第一条" —— 一次三控只在战报里写**一行摘要**，
   不是三行一样的话。

**可见性**：

* ★★ **被控住的人头顶冒「哈哈」** —— 和奶龙那套 😂 是同一套飘字特效
  （只是换字、换色）。眩晕原本只有一个很淡的金色小环，
  三控的时候三个环长得一模一样，分不清是"三个人被控住"还是"有个人在挨打"。
* 飘字之外还留着金色环 + 火星，施法者自己走通用的 `cast` 表现（紫环），
  所以"这三声哈哈是谁放的"也读得出来
* 回放：`🕶️【男人领域】嘉豪 把 b0、b1、b2 拖进了领域：眩晕 2.4 秒`
* ★ 巧乐兹的**冰冻不走这套表现**：它也是 `stun` 事件（`reason: 'freeze'`），
  但表现要更重（冰蓝大环 + 「冰冻」字幕）。给一个被冻住的人头顶冒 😂
  看起来像 bug —— 冰冻不是"被逗笑了"。

### 羊帆（原「火术士」）：羊巅峰 / 笑上巅峰 / 巅峰谢幕

`火术士` 改名 **羊帆**（id 仍然是 `pyromancer`），立绘换成 `art/pyromancer.png`。
技能换成 **「羊巅峰」**，而且这个角色**天生迟钝**：

| | |
| --- | --- |
| 移速 | **-80%**（走一格 0.3s → 1.5s） |
| 攻速 | **-80%**（0.66 → **0.132**，界面显示 0.13） |
| 技能 | **羊巅峰**：双眼射出激光蓄力，**下一次普攻伤害 ×20** |
| 收费 | 攻击计数型：开局白送一发，之后每 **2** 次普攻一发 |

| 星级 | 名字 | 多出了什么 |
| --- | --- | --- |
| 1★ | — | 只有技能本身（蓄力 → 下一次普攻 ×20） |
| 2★ | **笑上巅峰** | ×20 的那一下把目标**震晕 3 秒**，而且它会哈哈大笑 |
| 3★ | **巅峰谢幕** | 阵亡 1 秒后**原地自爆**：3×3 范围吃 **攻击力 ×20** 的物理伤害，活下来的还被震晕 3 秒 |

**一句话解释这个角色**：面板 DPS 只有 45 × 0.132 ≈ 5.9，看起来是一张废卡；
但它**每两次普攻就有一次 ×20**，等效倍率 10.5 倍。
"慢得离谱、但每一下都很重"就是它的全部性格。

六个实现上的判断：

1. ★★ **攻速直接写进 `def.as`（0.132），移速走 `slowMove` 字段。**
   攻速有面板项（卡片上显示 0.13），写进 `def.as` 之后
   "界面看到的数字 = 打出来的数字"这条老规矩继续成立 ——
   和荣誉「慢枪手」那一版是同一个做法。
   移速**没有**面板项（全场只有它和张雪峰会变），所以只能单独存一个 `movePct`。
   ★ 两者在 `moveMul` 里是**连乘**的：`u.movePct × (1 + ocMovePct) × 冰棍`。
   把 `movePct` 并进 `ocMovePct` 的话，一个迟钝 80% 的棋子吃到 +100% 会变成
   完全正常 —— 那不是"被加速了"，是"迟钝被治好了"。
2. ★★ **技能的收费方式改成「攻击计数」，和荣誉同一套。**
   走法力的话，0.132 攻速 = 7.6 秒才攒 10 点蓝，60 法力要 45 秒 ——
   一局只放得出一次技能，「下一次普攻 ×20」这个机制基本轮不到发生。
   改成计数（开局白送 + 每 2 次普攻）之后，一局能放 ~4 次，
   ×20 每 15 秒来一次。**这是这个项目里第三次踩同一个坑**
   （荣誉的 20% 命中率、奶龙的 13 秒冷却、羊帆的法力），
   所以现在有一条默认检查：**新技能先算「一局能触发几次」，再谈数值。**
3. ★ **蓄力是和荣誉共用的一段机制**（`charge` 事件 + `CHARGE_TIME`，
   渲染层画两只眼睛的金色激光）。区别只在"蓄完之后做什么"：
   荣誉是开枪，羊帆是给下一次普攻挂倍率。
   ★ 代价是校验器里那条「蓄力次数 ↔ 开枪次数」的账本**必须按技能类型分开记**
     —— 拿狙击的账本去对羊帆，每一条蓄力都会被判成"白开了"。
     **共用的是表现和管线，账本要各记各的。**
4. ★ **×20 乘在 `raw`（本该打出多少）上，不是直接改 `dmg`。**
   这样 `raw >= dmg`、"倍率 = 1 / 1.2 / 0.8"这些老自检全都继续成立，
   而飘字里的 `dmg` 会自然变成 20 倍（减伤照常吃）。
   ★ 消耗在**出手那一刻**，不是命中那一刻：一次蓄力换一次出手，
   和"自动寻敌不会浪费普攻"是同一个原则。
   ★ 蓄势只有"有/没有"两种状态，**不会叠成 40 倍**。
5. ★★ **3 星的自爆整套复用牢大的「坠机」管线**：同一个 `CFG.CRASH_DELAY`（1 秒）、
   同一个 `CFG.CRASH_RADIUS`（3×3）、同一套 `anyPending` 胜负挂账。
   区别只有两点：伤害是「攻击力 × 20」而不是固定值，以及炸完之后**不复活**。
   事件上也共用 `down` / `crash`，靠一个 `boom` 标记区分 ——
   渲染层看到 `boom` 就画"原地蓄力炸开"（`chargeGlow`），
   没看到就画"直升机砸下来"（`strike`）。
   **画成一样的话，玩家会以为羊帆也在召唤直升机。**
   ★ 伤害类型跟牢大一样是**物理**（吃护甲）：那是量出来的结论 ——
     900 点无视防御的伤害曾经把 20 关的难度余量砸出 +74% 的断崖。
6. ★ **巅峰一击 / 自爆附带的眩晕走 `reason: 'peak'` 的 stun 事件**，
   渲染层看到它就冒「哈哈」—— 和嘉豪「男人领域」是**完全同一套表现**。
   三个角色（嘉豪、羊帆的巅峰一击、羊帆的自爆）共用一套"被逗笑了"的视觉，
   加新角色时不需要再动 arena.js。

**可见性**：

* ★ 蓄力：两只眼睛射出金色激光（和荣誉同一条），0.5 秒后技能结算
* ★★ 蓄势徽章 `🐑×20`：**常驻在卡片上，一直到那一下真的打出去才消失**。
  这一枚是必须有的 —— 20 倍伤害是这个角色一整局唯一的高光，
  不挂徽章的话玩家只会看到伤害数字突然大 20 倍、以为算错了
* 巅峰一击：金红双环 + 大圈火星 + **1.9 倍字号的伤害数字**（暴击才 1.35 倍）
  + 顿帧 + 震屏，混战里一眼能认出"刚才那一下不是普通普攻"
* 自爆前 1 秒：一圈**越收越紧、越涨越亮**的红环（`chargeGlow`）+
  中心一颗在憋的火种 —— 和爆炸的"从中心炸开"刚好相反，
  "往中心收"本身就是"要炸了"的通用视觉语言
* 自爆：金红双环 + 台词「巅峰谢幕」；被震晕的敌人头顶冒「哈哈」
* 回放：`🐑巅峰一击 900（×20）` / `💥【巅峰谢幕】羊帆 自爆！3×3 范围受到 900 点物理伤害`

### 楚生疑犯（原「风语者」）：阴暗领域 / 同伙掩护 / 遁入暗影

`风语者` 改名 **楚生疑犯**（id 仍然是 `windcaller`），立绘换成 `art/windcaller.png`。
技能换成 **「阴暗领域」**，**范围翻倍**（半径 2 → **4**，9×9）：

| | |
| --- | --- |
| 领域 | 在目标格撑起一片**会变黑、会下雨**的区域，持续 **6 秒** |
| 对敌人 | 范围**内**攻速与移速**减半** |
| 对队友 | 2 星起：范围**内**少受 **30%** 的敌人伤害 |
| 伤害 | **一点都没有** —— 原来的 340 点范围伤害整条去掉了，它是纯地形/辅助 |

| 星级 | 名字 | 多出了什么 |
| --- | --- | --- |
| 1★ | — | 只有领域本身 |
| 2★ | **同伙掩护** | 领域里的队友少受 30% 的敌人伤害 |
| 3★ | **遁入暗影** | **每次放完技能**自己遁入暗影：攻速 ×0.5、伤害 ×2、**免疫一切伤害**、**不会被索敌**，直到**队友全部阵亡** |

五个实现上的判断：

1. ★★ **这是游戏里第一份「不属于任何单位」的持续状态。**
   以前所有"挂几秒"的效果都写在单位自己身上（`buffUntil` / `chillStacks`
   / `laughUntil`），人死了效果就跟着没了。领域不一样：施法者死了、走开了、
   被推走了，雨照样下、站在里面的人照样减半。
   所以它必须单独存一份（`st.fields`），**按时间戳过期** ——
   和别的持续状态同一套约定：不需要任何"结束"事件，谁读谁自己比时间。
   ★ 代价是数组会一直变长（一局最多几十条），但每个查询都会先比一次
     `until` 直接跳过，代价可以忽略。
2. ★★ **`field` 是一个新的 kind，不是 `aoe` 加了几个参数。**
   一次性结算的技能（aoe / whirl / nuke）和"留在地上的地形"在
   规则、事件、生命周期上都是两套东西 —— 硬塞进 aoe 会让那个分支
   变成"如果带了 dur 就……"，下一个读代码的人一定踩坑。
3. ★ **减速乘在"按比例减速"那一层**（`slowMul` = 冰棍 × 领域），
   和攻速加成是**乘**而不是加。理由和冰棍一样：它作用在"你现在的出手速度"上，
   并进加成里的话，一个叠满攻速的单位在领域里几乎不受影响。
   下限仍然保到 0.1 倍，防卡死。
4. ★ **2 星的减伤只挡敌方的伤害**（`src` 必须存在且是敌人），
   而且只在**圈里**。不挡自家伤害是刻意的：自爆 / 反伤被领域吃掉的话，
   那就不是"掩护"了。
   ★ 判定写在 `dealDamage` 的**减抗之后**，和捧腹大笑同一处 ——
     `raw` 保持"出手方本来能打多少"的含义，`dmg / raw` 那个比值才好用
     （自检就是靠圈内圈外的这个比值验出 0.7 的）。
5. ★★ **「直到队友全部阵亡」不是风味，是终止条件。**
   一个免疫一切伤害又不会被索敌的单位，如果永远不现形，
   对面既碰不到它也打不死它 —— 这场战斗只能拖到 60 秒读秒判平局。
   所以 `shadowTick` 里有一条硬规则：`aliveCount[自己这方] <= 1` 时**必须现形**。
   ★ 判定放在 `pendingTick`（坠机结算）**之后**、胜负判定**之前** ——
     复活会改 `aliveCount`，顺序反了会多躲一 tick。
   ★ 不会索敌是**两处**都要改：`acquireTarget`（新目标）和
     `nearestEnemyInRange`（射程内就地打）。只改一处的话，
     已经锁定过它的棋子会继续追着这个打不到的幽影满地图跑。
   ★ 免疫一切伤害拦在 `dealDamage` 最前面（和抓娃娃同一处），
     不限次数、不看来源 —— 反伤、自爆、AOE 全都打不动它。

**可见性**：

* ★★ **地面层**：一片径向渐变的黑（中心最暗 0.46，边缘化开）+
  **一串靠时间驱动的斜向雨丝** + 一圈虚线边界。
  ★ 画在**棋子下面、网格线上面** —— 它表达的是"这一片地面变黑了"，
    不是"天上飘了一个黑圈"；画在上面的话人就被一块黑布盖住了。
  ★ 雨丝的位置由**时间**算（不是每帧随机重画）：随机的话雨会闪成噪点。
  ★ 边界那圈虚线是必须的：渐变边缘是化开的，光靠渐变玩家判不出覆盖几格。
* ★ 遁入暗影：整张卡片压成 **0.42 透明度** + 冷色描边 + `🌑暗影` 徽章；
  进入 / 现形各弹一次台词（「遁入暗影」/「现形」）。
  ★ 一个"打不死也找不到"的单位，画面上不说清楚就变成了
    "对面集体发呆 + 我方有人不掉血" —— 那看起来就是 bug。
* 回放：`🌧️【阴暗领域】楚生疑犯 撑起一片阴暗领域：9×9 范围内变黑下雨…` /
  `🌑【遁入暗影】… 免疫一切伤害、也不会被索敌（队友还剩 1 个）`

### Dank1ng（原「神射手」）：先过中门再谈未来 / 空悲切 / 老男孩 / 锁头

`神射手` 改名 **Dank1ng**（id 仍然是 `deadeye`），立绘换成 `art/deadeye.png`。
技能从「贯穿之矢」换成 **「先过中门再谈未来」**：

| --- | --- | --- |
| 1★ | **空悲切** | 队友全部阵亡后**立刻恢复无限能量**（法力永远满格） |
| 2★ | **老男孩** | 开局满能量 |
| 3★ | **锁头** | 能量回复 **×2**，并且**每次击杀都把能量回满** |

**这个角色的三层是三条互不相干的规则**：1 星管"绝境爆发"、2 星管"开局节奏"、
3 星管"续航"。所以数据上是三个门槛（`startFullAt` / `regenMulAt` / `killRefillAt`），
`perHit` 只用来告诉界面"这一星级有没有被动"。

七个实现上的判断：

1. ★★ **「无限能量」的准确含义是"法力永远满格"，不是"一秒三十发"。**
   引擎里 `tryCast` **每个 tick 都会被调用一次**，所以"每 tick 回满法力"
   会变成一秒 30 发核弹 —— 那不是设计意图，是缺少节流。
   实现方式是顶在 `gainMana` 上（**只有涨法力的时候才顶满**），
   而"涨法力"只发生在两件事上：自己打了一下、自己挨了一下。
   于是出手频率被这两件事天然限住。
2. ★★ **新增 `CFG.CAST_LOCK = 0.5`：同一个单位两次施法之间至少隔半秒。**
   为什么必须有它：法力原本是**攒**出来的（一次普攻 +10 / 挨 25 点伤害 +1），
   这个攒的过程本身就是限速器；而「空悲切 / 锁头」会**把法力瞬间顶满**，
   限速器就没了 —— 尤其是挨打时：一次受击可能就是十几次 `gainMana`。
   0.5 秒是照着"一次出手"的量级定的：比攻速（0.82 → 1.22 秒/次）快一点，
   所以无限能量确实是实打实的提速，但不会快成连发。
   ★ 它对现有棋子是**空操作**：荣誉 3 次普攻 ≈ 3.7 秒、奶龙冷却 13 秒、
     其余法力型 6~9 次普攻 —— 没有一个能快到半秒一发。
3. ★ **「不贯穿」在数据上是 `line` → `nuke`，在自检上是"每次施法只打中一个人"。**
   只改数据是验不出问题的（旧版的 `length: 5` 只要还在，
   技能就会继续扫一整条线）；所以那条断言让三个敌人**排成一条横线**，
   再数每次施法打中几个人 —— 这正是旧版最吃香、新版最该打不中的位置。
4. ★ **击杀后续挂在 `checkDeath` 之上，不挂在技能分支里。**
   「锁头」的"击杀回满"用的是 `case 'death'` 里那句击杀统计
   （`u._lastHitBy.kills++` 旁边）—— 因为"击杀"不等于"被技能打死"：
   普攻打死的、反伤弹死的、坠机砸死的都算。
   ★ 顺带在 `death` 事件里加了一列 `by`（击杀者）：没有它的话，
     "谁杀的"在事件流里根本读不出来，那条"回满必须紧跟在自己的一次击杀之后"
     的断言也就无从谈起（回放顺便能写"X 击杀了 Y"）。
5. ★ **「耍刀 3 秒不攻击」是一个独立的封锁，不和「大笑」复用。**
   大笑是"很硬但不能还手"（也动不了），耍刀只是"忙着耍刀"——
   它照样走位、照样放技能，只有普攻被按住。所以是两个字段、两段判断。
   ★ 自检要**三头都验**：耍刀前在打、窗口内一次没打、窗口结束后又开始打。
     只验中间那条的话，"它本来就没在打"（比如被控住了）也能过。
6. ★ **骷髅"留在原地"靠的是一个几乎不飘的飘字**（`vy` 只有 -2% 格子/秒）。
   普通飘字是往上飞的设计，照抄的话"留在原地"就变成一句空话。
   寿命也拉到 1.8 秒，配一圈慢慢扩散的暗环，混战里能认出"这里死过人"。
7. ★ **「老男孩」的开局满能量和物品的蓝水晶是取大、不是相加**：
   一个是"开局给这么多"，一个是"开局就是满的"。

**可见性**：

* 技能击杀：尸体那一格留一个 💀 + 一圈暗环；回放写
  `💀 Dank1ng 的「先过中门再谈未来」击杀 X，在原地留下了一个骷髅`
* 耍刀：卡片周围一把**每 0.55 秒转一圈**的折叠刀（3 秒五圈半），
  外加一圈呼吸的金白描边 + `🔪耍刀` 徽章 —— 它同时是"这 3 秒它不攻击"的说明，
  不标的话玩家只会觉得"这个棋子卡住了"
* 刀收起来的那一帧，正好是它可以重新攻击的那一帧（`life` = `knifeDur`，
  和荣誉的激光、羊帆的自爆蓄力同一套约定）
* 空悲切：一圈暗红环 + 台词「空悲切」+ `♾️空悲切` 徽章；回放写
  `♾️【空悲切】队友全部阵亡，Dank1ng 的能量从此**无限**`
* 锁头：每次击杀法力条闪一下 + 一小撮火星（高频动作，不做大特效）

### 摆卡：点击和拖拽并存

原来只有「点棋子 → 点格子」这一种摆法，两次点击之间手是断开的：
点歪了要重来，摆一整排要来回点十几下。现在**两种都支持**。

* **拖拽**：按住任意棋子（备战席或棋盘上的），拖到目标格松手。
  可以拖到棋盘格、备战席空格、也可以拖到**已经有人**的格子（自动交换）
* 拖动时有跟着指针的幽灵卡、落点高亮虚线框；被拖的那张卡变淡
* **点击**照旧：不移动的「按下 → 松开」仍然是一次点击（选中 / 换位）

四个实现上的坑：

1. **用 Pointer Events，不用 HTML5 的 `dragstart`/`dragover`。**
   后者在触屏上根本不工作，而且要写一堆 `preventDefault` 才肯离开原元素。
   Pointer Events 一套代码同时覆盖鼠标 / 触屏 / 触控笔。
2. **移动和松开绑在 `document` 上，不是绑在棋盘上。**
   指针拖出棋盘再松手是常事，绑在容器上会漏掉一半操作。
3. **落点用 `elementFromPoint` 判定，幽灵卡必须 `pointer-events: none`** ——
   不然命中的永远是幽灵自己，「拖到哪一格」就永远算不出来。
4. **点击和拖拽共用同一套指针事件，靠"按下到松开之间有没有移动超过 6px"区分。**
   拖拽结束后浏览器还会补一发 `click`，必须吞掉（否则拖完会顺手再选中一次）。
   ★ 吞的方式是「**一次性开关** + 150ms 定时兜底」，不是时间戳窗口 ——
   一开始用 300ms 窗口，结果把 120ms 后的一次**正常点击**也吃掉了。
5. ★★ **必须掐掉 `<img>` 的原生拖拽** —— 否则「有立绘的棋子拖不动、没立绘的能拖」。
   浏览器对图片有 HTML5 drag-and-drop：在图片上按下再移动，它会启动原生拖拽，
   并且**取消整个指针序列**（发 `pointercancel`）—— 拖拽刚开始就被自己的
   `pointercancel` 收掉了。刷了立绘的棋子卡里正好有一个 `<img>`，
   emoji 兜底的没有，所以症状看起来是"改了图片之后就不能拖了"。
   三道防线一起上：`img.draggable = false`（标准路径）、
   `-webkit-user-drag: none`（老 WebKit）、`document` 捕获阶段拦 `dragstart`（兜底）。

★ 拖到备战席空位时要**放进用户指的那一格**，而不是像 `boardToBench` 那样
塞进第一个空位 —— 能指定位置正是拖拽相对"点两下"的全部价值。
第一版直接复用了 `boardToBench`，自检立刻报「备战席 3 号位是空的」。

★ 自检里另外钉了几条**共存性**：不移动的按下-松开必须仍然算点击
（这是"加了拖拽之后点不动了"这类回归的唯一防线）；
丢在空地之后不能有幽灵卡残留；落点必须真的能被 `elementFromPoint` 命中；
**卡片上的 `<img>` 必须 draggable=false** ——
合成出来的 PointerEvent 不会触发浏览器原生拖拽，所以"真的拖一下"测不出
原生拖拽那个 bug，能测的只有它的前提条件。

### 战后伤害占比

结算浮层底部多了一块**伤害占比**：每个上场棋子一行，
名字 → 横条 → `百分比 + 绝对值`，按伤害从高到低排。

* 只看**我方**的数据 —— 对面怎么分配伤害对玩家的下一步决策没有帮助
* 条长按「本队最高」归一化（不是按总和）：即使全队总伤害很低，
  第一名也是满条，一眼看出谁是主 C
* 同时给百分比和绝对值：只有百分比的话，一场 2000 伤害和一场 20000 伤害
  看起来一模一样
* 赢也看得、输更看得 —— 输的时候最想知道「到底是谁没打出伤害」，
  所以它放在 `if/else` 外面，两边都有

自检里钉住了四条：百分比加起来是 100%、条长都在 0~100%、
按伤害降序、第一名是满条。

### 5 费概率下调

6 / 7 / 8 级的 5 费概率从 **6% / 12% / 20%** 降到 **4% / 9% / 15%**
（约 −25%），让出来的份额**全给 4 费**（18→20、26→29、34→39）。

理由：5 费现在有山岳和张雪峰两个"一张就能定胜负"的角色，
再维持 20% 的话满级刷牌会退化成"谁先刷到五费谁赢"，把其它所有决策都盖过去。
份额转给 4 费而不是补回低费档 —— 4 费是当前内容最厚、也最需要凑 3 星的一档。

★ 概率表每行必须加起来等于 1（`simtest` 有断言守着），所以砍掉的份额
必须有地方去。自检里额外钉了两条：**概率不超过 4/9/15%**、
**满级 4 费不低于 36%**（后者钉的是"给了 4 费"这个设计意图本身）。

### 卡牌位置：比格子大，但绝不重叠

卡牌**故意比格子大**（宽 +6、高 +10），这是「不遵循格子」；
但位置必须严谨，靠三条保证：

1. **严格居中**：`.u { left:50%; top:50%; transform: translate(-50%,-50%) }`
   —— 溢出左右对称，所以「这张牌属于哪一格」永远一目了然（实测偏移 0px）。
2. **绝不重叠**：格子间距 `--gap = 8px` 大于横向溢出量的一半（3px），
   相邻卡牌之间始终留 **2px** 空隙。
3. **溢出不参与排版**：`.cell { overflow: visible }`，
   所以地图总尺寸永远等于 `8 格 + 7 个 gap`，卡牌怎么长都不会把布局撑歪。

这三条都由 `tests/gametest.html` 的几何断言守着（整排摆满 2 行 × 8 列，
逐张量中心偏移、同排和上下排的最小间隙）。之前只量一张卡，
量不出「相邻卡牌互相压住」这种问题。

### 这一段的坑，一句话总结

**「看不出来」不等于「没发生」。** `overflow: hidden` + 绝对定位的场景里，
溢出是被静静裁掉的：截图看着没问题、滚动条不出现、`scrollHeight` 也不变。
所以几何断言要直接比**矩形是否相交**，而不是看有没有滚动条。

## 五、接口速查

### 跑一场战斗

```js
var result = ST.Battle.battle({
  a: [{ id: 'titan', star: 2, items: ['dragonscale'], r: 3, c: 2 }],
  b: [{ id: 'bowman', star: 1 }]              // 不给 r/c 就自动站位
}, 20260101);                                  // 种子：数字或字符串
```

### 实验用选项（第三个参数）

| 选项 | 用途 |
| --- | --- |
| `recordLog: false` | 不生成日志，快 1.4 倍。批量跑上万场时用 |
| `noTraits: ['b']` | 让指定一方「羁绊只统计、不给加成」——做控制变量实验 |
| `statScale: { b: 1.2 }` | 把某一方全队面板乘一个系数 ——**让子标定**用 |

`statScale` 是这套工具里最有用的一个：镜像对局里任何优势都会放大成必胜，
所以光比胜率分不出强弱。改成「给对面加多少属性才打平」，
就能把任何东西（一个羁绊、一件装备、一次升星）换算成
**「等效 +X% 全属性」**这种能直接比较的数字。

### 游戏层的控制器 API

DOM 事件处理器最终都调这些函数。暴露出来是为了让集成测试能走**真实链路**：

```js
Game.start()                     // 新开一局
Game.state()                     // 当前状态（棋盘/备战席/商店/血量…）
Game.buy(shopIdx)                // 买商店第 i 张
Game.placeFromBench(bi, r, c)    // 备战席 → 棋盘
Game.reroll() / Game.buyXp()
Game.equip(bagIdx, uid)
Game.fight()                     // 开战
Game.retry() / Game.next()
Game.refresh()                   // 重新渲染
```

### 事件类型

`attack` `skill` `cast` `heal` `shield` `stun` `buff` `damage`(荆棘反弹)
`death` `move` `swap`(换位) `knockback`(肘击) `snap`(状态快照) `end`

星级被动 / 专属机制另外这些：
`frenzy`(越打越快) `gift`(幻觉/开智) `block`(抓娃娃) `ocas` `selfburn`(超频)
`chill`(冰棍) `laugh`(捧腹大笑) `down` `crash` `revive`(坠机 / 自爆三段)
`snipe`(狙击) `charge`(蓄力) `field`(阴暗领域) `shadow`(遁入暗影 / 现形)
`endless`(空悲切) `refill`(锁头回满) `skull`(技能击杀留骷髅) `knife`(耍刀)

★ 其中 `down` / `crash` 被两个角色共用（牢大的坠机、羊帆 3 星的自爆），
靠 `boom` 标记区分；`stun` 被四个来源共用，靠 `reason` 区分
（`freeze` 冰冻 / `domain` 男人领域 / `peak` 巅峰眩晕 / 缺省 = 普通眩晕）；
`block` 被两个来源共用（抓娃娃的"前 N 次"、暗影的"一切伤害"），
同样靠 `reason` 区分 —— **共用机制的时候，账本也要跟着分开**。
★ `death` 事件带 `by`（击杀者）：Dank1ng 的「锁头」要靠它验
「能量回满必须紧跟在自己的一次击杀之后」。

**日志里的血量/伤害一律是精确值，不做四舍五入** —— 取整会让
「`hpLoss` 必须等于血量差」这条最有力的自检失效。要好看是渲染层的事。

### 无尽模式：难度怎么「飙升」

24 关打完以后进入。对手不再来自 `ST.LEVELS`，而是 `ST.endlessWave(波次)` 现生成。
三个旋钮一起往上走：

| 旋钮 | 怎么涨 | 作用范围 |
| --- | --- | --- |
| 规模 | 7 人起步，每 3 波 +1，封顶 `ST.MAX_DEPLOY`(8) | 前 6 波 |
| 星级 | 2 星概率 0.80→0.98，3 星 0.37→0.60 | 前 10 波 |
| **面板** | **第 1 波 ×1.15，之后每波复利 ×1.07** | 全程，封顶 ×40 |

前两个只在前 10 波起作用 —— 因为「全员 3 星、满编 8 人」是个**天花板**，
撞到之后就没法再涨了。所以真正的无尽引擎是第三个：
**面板复利**。它连续、单调、可预测，而且不需要为每一波手写名字和台词。

实测面板倍率：第 1 波 ×1.15 → 第 10 波 ×2.11 → 第 20 波 ×4.15 →
第 30 波 ×8.16 → 第 40 波 ×16.0。玩家迟早会被推平，无尽自然有尽头。

两个设计细节：

* **起点必须接得住第 24 关。** 第一版从「3 人 / 最高 2 费 / 无加成」起步，
  结果刚打完最难的 BOSS，第 1 波反而变轻松了 —— 那读起来像「通关奖励」，
  不像「难度飙升」。现在第 1 波就是 7 人、直接抽 4/5 费、面板 ×1.15。
* **同一波永远生成同一份阵容**（`ST.makeRng(0x9e37 + wave * 7919)`，
  不用 `Math.random`）。否则玩家点「重试本波」就是在抽奖，
  而不是在针对一个确定的对手调整阵容。

### ⚠ 两个已经测出来、但故意留着的问题

1. **无尽之刃偏弱（对位 53.4%）**。它是个「纯粹放大暴击伤害」的乘算件 ——
   没配猎手之眼时收益几乎为零，配上了又只是把本来就赢的局赢得更快。
   （★ 上一版这条写的是「荆棘之甲偏弱」，靠**改机制**而不是改数值救回来了：
     见下面「讲话石」那一节。所以「垫底」先怀疑收益面是不是本身就窄。）
2. **预设阵容强弱跨度 50%**（理想 10%~35%）。四套阵容虽然总星级都是 10★、
   各带一个 4/5 费核心，但「狂战影袭」这种双高羁绊的玻璃大炮依然明显强过
   「游侠医者」。这是**体系级**问题，不是单卡问题。

### ⚠ 一个更根本的性质：这个战斗系统非常「断崖」

实测：两组**完全镜像**的阵容，只要把一边整体缩到 **94%**，胜率就直接从
100% 掉到 0%（缩到 96% 时大约在中间）。

也就是说：**面板差 4~6% 就能决定胜负，中间几乎没有过渡带。**

这是自走棋固有的雪球效应（先击杀 → 人数优势 → 集中火力 → 加速崩盘），
但我们的系统比云顶更极端。影响有两面：

- **好事**：平衡调起来很干脆，不用纠结「这 5% 到底有没有用」。
- **坏事**：落后的一方几乎没有翻盘空间，玩家会感觉「一开始就输了」。
  而且它让**连续标尺类实验失效** —— 装备强弱就没法用让子标定来测
  （断崖比任何一件装备的价值都窄），只能改用对位循环赛。

真要缓解，方向是削弱雪球：让单位定期重新选目标（而不是死盯一个打死为止）、
降低「加时赛」伤害递增的斜率、或者让技能伤害更分散。这三条都会让对局更
「有来有回」，但也会让平衡更难调 —— 属于设计取捨，不是 bug。

### 平衡实验的方法论

| # | 坑 | 症状 | 修法 |
| --- | --- | --- | --- |
| 8 | **羁绊实验拿「4 个羁绊棋子」对「4 个 1 费无羁绊棋子」** | 8 个羁绊全 100% —— 赢的是**费用**不是羁绊 | 控制变量：同一套棋子打自己，一边用 `noTraits` 关羁绊 |
| 9 | **镜像对局里任何优势都放大成必胜** | 8 个羁绊又是全 100%，完全没分辨力 | 改用**让子标定**（`statScale`），换算成「等效 +X% 全属性」 |
| 9b | **让子标定在 6 人高协同阵容上彻底失效** | 装备那一栏全是「超出量程」：龙鳞甲 +45%、疾风之靴 +3%，完全反直觉 | 实测断崖只有 4~6% 宽（镜像缩到 0.94 就是 0%），比任何一件装备的价值都窄。装备改用**对位循环赛**（两件不同装备直接对打，基线是真 50%） |
| 9c | **对位赛的判据写成了「每件装备都必须 >= 50%」** | 循环赛是零和的，必然有一件垫底 —— 这个判据永远会 FAIL | 改成守「垫底那件 >= 40%」和「整体跨度 < 30%」 |
| 9d | **装备实验拿另一个主 C 当固定对照** | 主 C 升到 4 费后基础战力碾压对照，基准胜率顶到 100%，圣杯被误判成废装备 | 对照组换成「同一个主 C 不带装备」的镜像 |
| 10 | **辅助函数忘了透传实验开关** | 让子实验全程在「不让子」上跑，又全报 100% | 加开关时记得在包装函数里透传 |
| 11 | **用「敌人总星级」当难度旋钮** | 胜率是**断崖**：L2 敌 3★=100%、敌 4★=0%，完全没法调细 | 1 星 = 面板 1.8 倍，跨度太大。改用连续的 `statScale` 当标尺 |
| 12 | **扫描门槛的方向写反了** | 十关一起报 −60%，看起来像难度爆炸，其实是量尺错了 | `statScale` 加在参考方身上 → 胜率随系数**递增**，交叉判据要跟着反过来 |
| 13 | **战力集中 ≠ 战力总量** | 同为 8 总星级，「1 个 3 星 + 5 个 1 星」100% 赢「均匀 2 星」 | 比较阵容强度不能只看总星级 |
| 14 | **羁绊协同 >> 面板数值** | 我给敌人配了成型羁绊、给参考阵容配了散卡，第 1 关 0% 过关率 | 两边都必须是「成型的体系」，强度差靠星级和人数控制 |

## 八、下一步该做什么

### 第一优先：把「对战模式」做出来

现在它是锁着的。真要做得先解决三件事：

1. **服务器**。模拟器是确定性的，所以理论上「只同步双方阵容 + 种子，各自本地算」
   就能实现 —— 架构已经留好了口子。但需要一台服务器做匹配和转发。
2. **对手阵容的可见性**。现在人机模式刻意藏起对手阵容。真人对战里
   要不要给「侦查」功能，是个设计问题（云顶是能看别人棋盘的）。
3. **掉线与反作弊**。种子同步方案下，客户端改阵容就能作弊，需要服务端校验。

### 第二优先：数值打磨

`balancetest.html` 已经把该调的三个点列出来了（见第六节）。
调完重跑那一页，看三件事：同费超模卡有没有冒出来、1v1 档内榜的极值、
时长分布有没有塌到两端。

★ **目前 balancetest 有 2 条是红的**（其余三套全绿），两条都在「装备收益」那一节：

```
装备强弱差距不至于让选择失去意义（跨度 < 30%）   实测 32.5%
没有一件装备强到无脑必抢（对位胜率 < 85%）      巨力之刃 85.5%
```

**这是一条早就存在的数值信号，不是 bug**，也不影响玩。根因是**那套对位赛的比法**：
它是「主 C 身上只换这一件」，所以任何**输出属性**的装备天然会赢过防御属性的
（榜单前三 巨力之刃 / 秘法之书 / 疾风之靴 全是输出属性）。
试过把巨力之刃从 +25% 削到 +20%：只从 85.7% 掉到 85.5%，几乎没动 ——
说明要解决得改**比法**（比如按"装备类型 × 主 C 类型"分组比较，或者看胜率分布而不是"最好的那一路"），
而不是改这一行数值。所以先把数值留着，等你做平衡那一轮一起处理。

### 第三优先：内容与体验

- **共享棋子池**（每种棋子有限张数，让「抢卡」成为策略）
- **装备合成**（两件小件合一件大件 —— **内容稳定之后再加**，它会让数值调试复杂度翻十倍）
- **更多棋子与羁绊**（加完必须跑 `balancetest.html` 守住平衡）
- **战斗表现**：伤害飘字、技能特效、击杀慢镜。`arena.js` 已经是纯消费事件流的，
  加特效不用碰规则
- **音效**：现在是 WebAudio 现场合成的（零依赖），要更好的声音就得引入音频文件

### 移动端

**已经能玩了**（见第零节「手机上是怎么排版的」）：
700px 以下（或者窗口高度 ≤520px，横屏手机走这条）自动折成一列布局，
棋盘、商店、备战池都按宽度重新算，`gametest` 的「手机竖屏布局」那一组守着它。
触屏上的拖拽/点击本来就是 pointer 事件，不用改。

还差的是**手感层面**：目前是键鼠（空格暂停、`~` 调试数字），
手机上没有对应的按钮 —— 暂停有按钮，调试数字没有。
另外手机上侧栏内容要往下滚，比桌面多一次滚动。
